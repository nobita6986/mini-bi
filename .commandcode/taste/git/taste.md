# Git

- Forbids amend, rebase, force-push, merging `main`, and modifying the primary checkout. Confidence: 0.9
- Before reporting a task as done, commits and pushes fast-forward to the correct branch, then verifies local HEAD == remote HEAD and a clean worktree. Confidence: 0.9
- Migrations are append-only: never modify existing migrations; a new migration is created only when the task truly needs one, its next slot is derived from the actual base at implementation time, and slots are never pre-reserved. Confidence: 0.9
- Derives the migration's next slot from the actual Production DB ledger (e.g. Vercel's `schema_migrations`) rather than the `origin/main` migration count alone: an already-applied migration from a still-unmerged branch must be brought into the branch and the new migration placed in the following slot, with the repo-side checksum reconciled against Production's `schema_migrations.checksum` — an offline `N/N` only proves local ordering, not that the slot matches Production. Confidence: 0.8
- Preserves existing data when planning changes/migrations: never deletes records, never merges by email, never changes UUIDs, and never automatically attaches/links records without a proven explicit relationship. Confidence: 0.7
- Uses explicit refspecs when pushing so the branch cannot accidentally push to `main`. Confidence: 0.6
- On branch/main divergence where a fast-forward update is impossible, stops and escalates for an explicit reconciliation decision rather than rewriting history; when approved, prefers an additive merge of origin/main into the feature branch (keeping both sides' work present exactly once) over rebase/amend/force-push. Confidence: 0.7
- Distinguishes the branch's fixed ancestry base SHA from the current origin/main: the base recorded at branch creation stays the ancestry base and is never rebased, while the current origin/main is tracked separately and consulted only for a factual-delta check (it is not a branch ancestor and main is never merged into the feature branch). Confidence: 0.6
- Uses conventional commit messages in English (`feat(<scope>)` / `docs(<scope>)` subject lines) with a multi-line body summarizing the behavior, scope boundaries, and gate/test results, plus a `Co-authored-by: CommandCodeBot <noreply@commandcode.ai>` trailer — even though communication with the user is in Vietnamese. Confidence: 0.8
- When reporting Git identity, prints only the effective `user.name`/`user.email` with their configuration source (system/global/local/worktree) rather than dumping the full Git config. Confidence: 0.7
- When the user asks whether a specific commit was pushed (e.g. "did you push this fix?"), confirms with the exact commit SHA and clarifies the commit's actual nature (e.g. docs/handoff vs implementation code) instead of giving a blanket confirmation. Confidence: 0.6
