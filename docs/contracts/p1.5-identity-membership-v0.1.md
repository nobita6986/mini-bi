## 1. Identity contract

| Entity | Field bắt buộc | Ghi chú |
|---|---|---|
| Recruiter | `recruiter_id` (stable), `display`, `active` | `display` chỉ phục vụ server/UI và **không bao giờ** là identity |
| Recruiter alias | `alias_id`, `recruiter_id`, `reporting_key`, `valid_from`, `valid_to` (nullable), `active` | `reporting_key` = key đã chuẩn hóa từ reporting layer |
| Team | `team_id` (stable), `code`, `display`, `active` | `code`/`display` không phải identity |
| Provider membership | `membership_id`, `recruiter_id`, `provider_type` (`hrp`/`vendor`), `valid_from`, `valid_to` | Hiệu lực theo thời gian |
| Team membership | `membership_id`, `recruiter_id`, `team_id`, `valid_from`, `valid_to` | Hiệu lực theo thời gian |
| Audit projection | `change_id`, `version`, `entity`, `ref`, `before_revision_ref`, `after_revision_ref`, `actor_ref`, `reason`, `effective_date`, `recorded_at` | Không PII, không secret; `actor_ref` là opaque reference |

- **Không** đồng nhất recruiter với app user. Cùng một người thật chỉ được liên kết **sau này**
  bằng mapping explicit của P1.6.
- Alias có effective date (`valid_from`/`valid_to`) để đổi key theo thời gian mà không viết lại lịch sử.

## 2. Interval semantics

- Mọi membership dùng interval **nửa mở** `[valid_from, valid_to)`; `valid_to = null` nghĩa là còn hiệu lực.
- `valid_from` **thuộc** khoảng; `valid_to` **không thuộc** khoảng.
- So sánh theo `business_date` dạng `YYYY-MM-DD` (lexicographic = chronological).
- Membership đã retire **không** viết lại fact quá khứ: fact trước `valid_to` vẫn map theo membership cũ.

## 3. Resolver (pure, deterministic)

Input mỗi fact: `business_date`, `recruiter_key`, `provider_type_key` (từ fact), `recruited_count`.

Thứ tự resolve:

1. **Recruiter alias**: chuẩn hóa `recruiter_key` (NFC → trim → gộp khoảng trắng → lowercase) rồi khớp **exact**
   với `reporting_key` của alias `active` có hiệu lực tại `business_date`.
2. **Team membership** của recruiter đã resolve, hiệu lực tại `business_date`.
3. **Provider membership** của recruiter, hiệu lực tại `business_date` — chỉ để so với provider fact.

**Không** suy identity từ display, source filename, project hay account. **Không** âm thầm chọn một record khi overlap.
Kết quả luôn được sort ổn định theo `(business_date, recruiter_key, provider_type_key, recruited_count, classification, reason_codes)`
nên **không** phụ thuộc thứ tự input/DB.

### 3.1. Classification

| Classification | Điều kiện |
|---|---|
| `mapped` | đúng **một** recruiter VÀ đúng **một** team membership |
| `unmapped` | thiếu recruiter (alias không có / key sentinel / key rỗng) **hoặc** thiếu team membership |
| `ambiguous` | alias overlap **hoặc** team membership overlap (nhiều kết quả hợp lệ cùng ngày) |

### 3.2. Missing / ambiguous / provider mismatch

| Tình huống | Reason code | Hệ quả |
|---|---|---|
| Không có alias hiệu lực | `RECRUITER_ALIAS_NOT_FOUND` | unmapped |
| `recruiter_key` là `__unknown__`/`__invalid__` | `RECRUITER_KEY_SENTINEL` | unmapped, **không** tự gán team |
| `recruiter_key` rỗng/không hợp lệ | `RECRUITER_KEY_INVALID` | unmapped |
| Nhiều alias cùng key cùng ngày | `RECRUITER_ALIAS_AMBIGUOUS` | ambiguous |
| Không có team membership | `TEAM_MEMBERSHIP_NOT_FOUND` | unmapped |
| Nhiều team membership cùng ngày | `TEAM_MEMBERSHIP_AMBIGUOUS` | ambiguous |
| Không có provider membership | `PROVIDER_MEMBERSHIP_NOT_FOUND` | quality issue, classification không đổi |
| Nhiều provider membership cùng ngày | `PROVIDER_MEMBERSHIP_AMBIGUOUS` | quality issue, classification không đổi |
| Provider membership khác provider fact | `PROVIDER_MISMATCH` | quality issue riêng; **KHÔNG** overwrite provider fact |

## 4. Team coverage output (map trực tiếp `team_mapping` R2)

```
{ availability, mapped_recruited_count, unmapped_recruited_count, ambiguous_recruited_count,
  coverage_ratio, teams_in_scope, reason_code }
```

Invariants (đã test):

1. `mapped + unmapped + ambiguous = tổng recruited_count của input`.
2. Coverage **fact-weighted** theo `sum(recruited_count)` — **không** đếm row grain.
3. `ambiguous > 0` ⇒ `availability = ambiguous` và `teams_in_scope = 0` (không phát team subject/driver).
4. `mapped > 0` + `unmapped > 0` + `ambiguous = 0` ⇒ `partial`.
5. Toàn bộ mapped (`unmapped = ambiguous = 0`, `mapped > 0`) ⇒ `available`.
6. `mapped = 0` và `ambiguous = 0` ⇒ `unavailable`.
7. `available`/`partial` với tổng > 0 ⇒ `teams_in_scope >= 1`.
8. Tổng `= 0` ⇒ `coverage_ratio = null`; ngược lại `coverage_ratio = mapped / tổng`.
9. Unknown/invalid recruiter **không** được tự gán team.
10. `reason_code` ∈ `TEAM_MAPPING_AVAILABLE` / `TEAM_MAPPING_PARTIAL` / `TEAM_MAPPING_UNAVAILABLE` / `TEAM_MAPPING_AMBIGUOUS`.

## 5. Opaque references

- `recruiter_id`/`team_id` **không** được gửi trực tiếp cho AI.
- Packet-facing output chỉ chứa `recruiter_ref` (`recruiter_01`…) và `team_ref` (`team_01`…), tạo **deterministic trong cùng frozen packet**:
  sort stable id rồi đánh số từ 01.
- Không dùng display hoặc tên thật trong projection.
- `ref_map` (ref → stable id) **chỉ** dùng server-side/UI sau validation (`resolveRefForDisplay`).
