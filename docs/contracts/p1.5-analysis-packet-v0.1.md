## 1. Câu hỏi kinh doanh đã khóa (W01)

Report phải trả lời được, có bằng chứng:

1. Kết quả đang **tăng, giảm hay đi ngang**?
2. Phần thay đổi chủ yếu đến từ **team/recruiter/project/provider/employment/thời điểm** nào?
3. Kết quả **ổn định hay dao động**?
4. Có **phụ thuộc quá nhiều** vào một team/recruiter/project/Vendor không?
5. **Cơ cấu HRP/Vendor** và **Thời vụ/Chính thức** thay đổi ra sao?
6. **Điểm mạnh** nào có bằng chứng?
7. **Điểm cần cải thiện/rủi ro** nào có bằng chứng?
8. **Chất lượng dữ liệu** có làm giảm độ tin cậy không?
9. BoD nên **kiểm tra hoặc hành động** gì tiếp theo?

Giới hạn trình bày: **3–7 findings** quan trọng mỗi report, **tối đa 3 recommended actions**.

## 2. Kỳ phân tích

| Loại | Định nghĩa |
|---|---|
| `week` | Thứ Hai → Chủ Nhật, Asia/Ho_Chi_Minh |
| `month` | Tháng dương lịch |
| `quarter` | Q1–Q4 |
| `custom` | `from/to` hợp lệ |

- Kỳ chưa kết thúc ⇒ `status = "period_to_date"`, `period_to_date = true`.
- PTD **chỉ** so với cùng số ngày đã trôi qua của kỳ trước: `comparable.elapsed_days = period.elapsed_days`
  (validator từ chối nếu khác). Không so kỳ đang chạy với toàn bộ kỳ hoàn tất.
- `end` luôn là ngày kết thúc **lịch** của kỳ; `elapsed_days` là số ngày đã trôi qua.

### 2.1. Baseline an toàn (sufficiency)

| Key | Ý nghĩa | Tối thiểu |
|---|---|---|
| `trend_weekly` | Trend tuần | 4 tuần hoàn tất |
| `trend_monthly` | Trend tháng | 3 tháng hoàn tất |
| `trend_quarterly` | Trend quý | 4 quý hoàn tất |
| `day_of_week` | Pattern theo thứ | 8 tuần |

- `required_points` **phải** đúng bảng trên (validator từ chối nếu lệch).

- Không đủ baseline vẫn được phân tích **contribution/concentration**, nhưng **không** được `confidence = high`.

## 3. Nguyên tắc công bằng (bắt buộc)

**Không được:**

- Gọi một người/team là “yếu”, “kém hiệu quả” chỉ vì volume thấp.
- Kết luận năng lực khi chưa có target, active working days, workload hoặc độ khó dự án.
- Khẳng định nguyên nhân ngoài dữ liệu.
- Dùng giới tính, tuổi, địa chỉ, CCCD, SĐT, ngân hàng hoặc PII ứng viên.
- Gán unknown/invalid thành lỗi cá nhân khi chưa xác định owner.
- So sánh cá nhân ngoài cohort hợp lệ.
- Dùng báo cáo AI để tự động kỷ luật, thưởng/phạt, điều chuyển hoặc chấm dứt lao động.

**Được phép phân tích:** momentum · consistency/volatility · contribution · diversification ·
concentration · data-quality risk · provider dependency **có bằng chứng**.

## 4. Shape `analysis-packet/0.1`

Strict object (mọi cấp `.strict()` — field lạ bị từ chối với `UNKNOWN_FIELD`).

| Nhóm | Field |
|---|---|
| Contract | `contract_version` |
| Snapshot/lineage | `generated_at`, `snapshot.hash`, `snapshot.lineage_ref`, `snapshot.generated_from` |
| Scope/access | `scope.scope_hash`, `scope.access_scope_hash`, `scope.sources_in_scope`, `scope.dimensions[]` |
| Period | `period.period_ref`, `type`, `start`, `end`, `timezone`, `status`, `period_to_date`, `elapsed_days`, `comparable{...}` |
| Totals | `totals.current`, `totals.comparable`, `totals.delta`, `totals.delta_pct` |
| Drivers | `drivers.project[]`, `recruiter[]`, `team[]`, `provider[]`, `employment[]` — mỗi entry: `subject_ref`, `current`, `comparable`, `delta`, `delta_contribution_share`, `share_of_current` |
| Concentration | `concentration.{project,recruiter,team,provider,employment}` — `top1_ref`, `top1_share`, `top3_share`, `distinct_subjects` |
| Stability | `stability.period_points`, `mean`, `stddev`, `cv`, `trend_direction`, `volatility` |
| Series | `series.granularity` (`day`/`week`), `series.points[]` = `{ period_start, period_end, value }` |
| Data quality | `data_quality.sources[]` (`source_ref`, `status`, `quality`), `coverage_ratio`, `unknown_count`, `invalid_count`, `unknown_share`, `invalid_share` |

### 4.1. Evidence record

Mỗi evidence **bắt buộc** có:

| Field | Ghi chú |
|---|---|

| `metric` | metric key có cấu trúc (`^[a-z][a-z0-9_.\[\]-]{0,63}$`) |

## 5. Opaque subject ref (bắt buộc)

| Loại | Dạng | Ví dụ |
|---|---|---|
| Project | `project_NN` | `project_01` |
| Recruiter | `recruiter_NN` | `recruiter_03` |
| Team | `team_NN` | `team_02` |
| Provider | `provider_{hrp\|vendor\|unknown\|invalid}` | `provider_vendor` |
| Employment | `employment_{seasonal\|official\|unknown\|invalid}` | `employment_seasonal` |
| Toàn scope | `scope` | `scope` |

- Display name **không** nằm trong packet; chỉ resolve server-side/UI sau validation.
- `catalog_key` (nullable) giữ key nghiệp vụ đóng cho provider/employment: `hrp`, `vendor`, `__unknown__`,
  `__invalid__`, `thời vụ`, `chính thức`.
- Mọi chuỗi trong packet đều bị **schema hóa** (regex/enum/ISO date/hash), nên nhãn tự do từ Google Sheets
  không thể lọt vào packet.

## 6. R7 — project × provider mix trong packet

`project_provider_mix[]` = `{ subject_ref, project_total, hrp_count, vendor_count, unknown_count, invalid_count,
known_total, hrp_share, vendor_share, known_coverage }`, giữ nguyên semantics R7:

1. Dùng `recruited_count`, **không** đếm dòng grain.
2. `unknown/invalid` **không** vào tử số và **không** vào mẫu số `hrp_share`/`vendor_share`.
3. `known_total = 0` ⇒ `hrp_share = vendor_share = null` (UI hiển thị “Không đủ dữ liệu phân loại”, không hiển thị 0%).
4. `project_total = hrp + vendor + unknown + invalid`; `sum(project_total) = totals.current`.
5. Không tự đặt ngưỡng “phụ thuộc Vendor cao”; chỉ “Vendor chiếm đa số” khi `vendor_share > 0.5` (**kết luận toán học**).
6. Nếu muốn gọi là `risk`, finding phải kèm limitation (concentration, sample size, coverage).

## 7. Nội dung bị cấm (scan toàn bộ packet trước khi schema)

| Nhóm | Reason code |
|---|---|
| PII | `PII_EMAIL`, `PII_PHONE_VN`, `PII_CCCD`, `PII_DOB` |
| Secret | `SECRET_OPENAI_KEY`, `SECRET_JWT`, `SECRET_NAMED_KEY`, `SECRET_SUPABASE` |
| Prompt injection | `PROMPT_INJECTION_OVERRIDE`, `..._SYSTEM`, `..._TEMPLATE`, `..._TOOL` |

Packet **không** chứa: raw candidate row · PII ứng viên · source filename/Drive ID · raw prompt · API key ·
tên thật của recruiter/team/project trong payload.

## 8. Reason codes (validation)

`UNKNOWN_FIELD` · `SCHEMA_INVALID` · `PERIOD_RANGE_INVALID` · `PERIOD_STATUS_MISMATCH` ·
`PTD_COMPARABLE_REQUIRED` · `PTD_ELAPSED_MISMATCH` · `DUPLICATE_EVIDENCE_ID` · `SNAPSHOT_REF_MISMATCH` ·
`SCOPE_REF_MISMATCH` · `PERIOD_REF_MISMATCH` · `UNKNOWN_SUBJECT_REF` · `DUPLICATE_SUBJECT_REF` ·
`TOTAL_DELTA_MISMATCH` · `SUFFICIENCY_REQUIRED_MISMATCH` · `SUFFICIENCY_STATUS_MISMATCH` ·
`CONCENTRATION_INVALID` · `PROJECT_MIX_DUPLICATE` · `PROJECT_MIX_INVARIANT` · `PROJECT_MIX_TOTAL_MISMATCH` ·
`DATA_QUALITY_INVALID` + các code PII/secret/injection ở §7.

Validator **không bao giờ** trả packet một phần: hoặc `{ ok: true, value }` hoặc `{ ok: false, code, message, path }`.

## 9. Quy trình validate

1. `scanProhibitedContent` (đệ quy mọi string) — dừng ngay nếu có nội dung bị cấm.
2. Strict schema (`z.strictObject` + superRefine cho period).
3. `checkPacketSemantics`: evidence → subjects → totals → sufficiency → concentration → mix → data quality.
