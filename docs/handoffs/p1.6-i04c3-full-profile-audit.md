## 3. Executive summary

T1C has read the full P1.6 Direct Entry database surface (34 migrations) and the related TypeScript contracts, and has produced a **policy / contract proposal** for the full worker profile superset that the business wants. On 2026-10-04 T0 locked all 12 open decisions (D11–D22) plus three architectural locks (A1–A3). The proposal is built around four observations:

1. **The current schema covers ~70% of the superset.** Fields B1–B7, C1, C3, C5, C8, C9, D1, D2, E1–E4, F1–F4, G1–G3 are already supported. The contract `WorkerDetails` (`src/lib/contracts/direct-entry-v1.ts:69`) defines 5 fields, and the `direct_entry_valid_worker_details` JSONB validator (`20261002170000_…:127–184`) enforces them. PII redaction at read time is layered: list projection (S03CD) is PII-clean; detail projection (S04A) masks `payment.account_number` last-4 if no `payment_view`; revision snapshots are redacted at write time (S03B3-R1) so new revisions are PII-clean.

2. **The remaining ~30% was genuinely missing; now it's T1B-implementation work.** Fields C2 (`gender`, D11: `MALE`/`FEMALE`/`OTHER`), C6/C7 (`national_id_issued_at` / `national_id_issued_place`, D15), B8 (`general_note`, D13: entry-level ≤ 4000) are now **locked** and will be added by T1B. The catalog boundary (G10/G11/G21) is **approved via I04C2B** and is **in flight in T1B as migration #35** (D17).

3. **Two production blockers existed; one is in flight.** Per I04C2A: (a) Production has **0 active banks**, **0 projects**, **0 recruiters**, **0 teams**; (b) the database has **no sanctioned, audited master-catalog write boundary**. The catalog boundary is **APPROVED via I04C2B** (D17) and T1B is amending migration #35. Until #35 lands, full-profile smoke on Production remains gated. T1C has flagged the post-merge reconciliation items as G10 / G11 / G21 in the matrix doc.

4. **T1A R2's paste model is partial.** `7a3a04c` implements a fixed 6-column paste. A1 / D4 lock the target as a **single superset, header-based template**, with optional columns and no second parser. T1A must rebuild the parser against `worker-profile/1.0` (header alias resolution; `Mã NLĐ` is canonical display, `Mã số ứng viên` is import alias only; no fixed N-column model — T01 acceptance test now says "minimal required profile", not "5 columns").

The matrix doc fixes a `worker-profile/1.0` contract version (separate from `direct-entry/1.1`), confirmed by T0 (D18: no new capability; reuse the existing 21). The 12 T0-locked decisions are catalogued in §1 (D11–D22) and surface in §3, §4, §5, §6, §7, §8, §10, §11 of the matrix doc.

### 5.1 T1B (server foundation)

The T1B migration extends the schema per the locks, and adds the new full-profile batch RPC. The plan is:

1. **Migration #35+** (D11/D13/D15/D17/D22):
   - Extend `direct_entries.worker_details` JSONB with `gender` (D11: `MALE`/`FEMALE`/`OTHER`), `national_id_issued_at` (D15), `national_id_issued_place` (D15).
   - **Add top-level** `direct_entries.general_note text` (D13: ≤ 4000 chars, **not** inside `worker_details`).
   - Update `direct_entry_valid_worker_details` to accept the new keys.
   - Add `direct_entry_create_full_profile_batch` RPC (A1: single superset contract; §5.1 of the matrix doc specifies the atomic-batch semantics across entry / worker_details / payment / historical status event).
   - Update `direct_entry_update_draft_row` to accept the full `worker_details` shape (not only `display_name`).
   - Update `direct_entry_apply_change_item` ENTRY_FIELD branch to accept the new fields.
   - Update `direct_entry_change_request_required_capabilities` and `direct_entry_change_request_proposal_projection` for the new fields.
   - Update `direct_entry_list_own_drafts` projection to include `gender`, `national_id`, `phone`, `address`, `general_note` **only if `pii_view` is present** (otherwise PRESENCE_ONLY).
   - Update `direct_entry_input_catalog` to include `teams[]` and `banks_active_count`.
   - Add search indices (D22, A2): `lower(employee_code)`, **`lower(worker_details->>'display_name')` text_pattern_ops** (note: `display_name` is a plain string, not an `OptionalValue`), partial btree on canonicalized `national_id` (9 or 12 digits, leading-zero preserved, `state = 'provided'`).
   - **Bump contract version** to `worker-profile/1.0` (A1; **do not** reuse `direct-entry/1.1`).
   - **Do NOT** add a master-catalog write boundary in this migration; that is **migration #35** (D17: approved via I04C2B, in flight in T1B).
   2. **Backwards compatibility**:
   - Existing 5-key `WorkerDetails` continues to validate; new keys are optional (A1: optional columns may be absent).
   - Existing 6-key batch (`project_id, first_work_date, employee_code, worker_details, recruiter_id, labor_type`) continues to validate.
   - New RPC is **additive**; old RPC is not removed.

3. **Atomic full-profile batch** (D13, D16):
   - One transaction per batch submission.
   - Capability union check at the entry of the RPC (mirroring S03B3-R1 `direct_entry_decide_change_request` line 401; D18: reuse the 21 existing capabilities — no new capability).
   - If any row's capability union is incomplete, the entire batch is rejected (no partial commit).
   - If any row's catalog/employee_code/recruiter/payment/status validation fails, the entire batch is rejected (no partial commit).
   - Historical `OFF` event (D16) requires `employment_status.apply` on the actor.

4. **Payment / work-status atomicity**:
   - `direct_entry_update_payment` already atomic per entry; unchanged.
   - For an initial `OFF` event (D16: historical only), introduce a new `direct_entry_apply_initial_status_event` RPC that runs in the same transaction as the entry creation.

5. **CCCD boolean projection**:
   - Existing `direct_entry_read_projection` already returns the document array; verify it never includes `idempotency_key`, `checksum_sha256`, `size_bytes`, `mime_type` in the response (it does NOT today, by design).
   - Add a server-side helper `documentCompletenessByEntry(entryId)` that returns `{ CCCD_FRONT, CCCD_BACK, EMPLOYMENT_CONTRACT }` counts of `READY+VALIDATED+(CLEAN|NOT_REQUIRED)` documents.

6. **Search readiness** (per matrix §7; D22):
   - New RPC `direct_entry_search_profile` (or extension of `direct_entry_list_own_drafts` with `query` parameter) that takes `query` text and `page_size` / `cursor` and returns masked PII if no `pii_view`.
   - **A2 / D22**: search index is **`lower(worker_details->>'display_name')`** (plain string), **NOT** `lower(worker_details->'display_name'->>'value')`. The first audit draft used the wrong path; this is the correction.
