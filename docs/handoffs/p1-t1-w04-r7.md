## 1. Mục tiêu
Card full-width **“Tỷ lệ HRP/Vendor theo dự án”** giúp BoD biết dự án nào có tỷ trọng tuyển dụng từ Vendor cao nhất. Tính trực tiếp từ grain hiện có:

`source + business_date + project + recruiter + provider_type + employment_type = recruited_count`

Không mở lại ingestion, không đổi số liệu hiện có, không thêm query riêng (dùng chính tập facts đã phân trang và filter).

## 2. Công thức (mỗi `project_key`)
| Field | Công thức |
|---|---|
| `projectTotal` | `sum(recruited_count)` toàn bộ provider trong dự án |
| `hrpCount` / `vendorCount` | `sum` khi `provider_type_key = 'hrp'` / `'vendor'` |
| `unknownCount` / `invalidCount` | `sum` khi `'__unknown__'` / `'__invalid__'` |
| `knownTotal` | `hrpCount + vendorCount` |
| `hrpShare` / `vendorShare` | `count / knownTotal` — **null** khi `knownTotal = 0` |
| `knownCoverage` | `knownTotal / projectTotal` |

Quy tắc: dùng `recruited_count` (không đếm dòng grain) · unknown/invalid **không** vào tử số và **không** vào mẫu số share · `projectTotal = hrp + vendor + unknown + invalid` · `knownTotal > 0 ⇒ hrpShare + vendorShare = 1` · group theo `project_key`, display theo `selectDisplay` · không đặt ngưỡng rủi ro tùy ý (chỉ “Vendor chiếm đa số” khi `vendor_share > 0.5` — kết luận toán học).

## 4. Invariants (đã test + verify live)
1. `projectTotal = hrpCount + vendorCount + unknownCount + invalidCount` cho **mọi** dự án.
2. `sum(projectTotal)` = `recruitedTotal` trong cùng filter.
3. `knownTotal > 0 ⇒ hrpShare + vendorShare = 1`; `knownTotal = 0 ⇒ cả hai = null` (không NaN/Infinity).
4. unknown/invalid không vào tử số và mẫu số share.
5. Fixture `is_test=true` vẫn bị loại; sentinel project vẫn hiển thị (đặt cuối).
6. Top 10 + “Xem chi tiết tất cả” **không** làm mất dữ liệu.
