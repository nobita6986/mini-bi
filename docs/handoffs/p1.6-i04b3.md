## Scope and behavior

- **Change-request create:** only `ENTRY_FIELD`, `PAYMENT`, and `WORK_STATUS`.
  DOCUMENT and mixed DOCUMENT requests fail with sanitized 400 before session
  or repository dispatch. Migration #34 remains the final DB invariant.
- **Sensitive UI:** supports `worker_details`, PAYMENT, and WORK_STATUS. Historical
  DOCUMENT proposals are strict-projected to safe metadata and remain read-only;
  they cannot be approved or rejected. No checksum, storage key, bucket, or URL
  is exposed.
- **Submitted documents:** the SUBMITTED submission manager fetches submission
  detail, uses returned `entry_ids` to load strict entry projections, and uses
  the direct document upload API. Replacement reason is required. Flow is
  reserve → signed PUT → finalize; the manager does not call the change-request
  API. DRAFT behavior remains unchanged and REVIEW has no manager action.
- Capability/scope, OCC/idempotency, RLS/ACL, Basic Auth proxy, and server-side
  navigation gates were not weakened.
