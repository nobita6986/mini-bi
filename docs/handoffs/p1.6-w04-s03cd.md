## Implementation

The forward-only migration
`20261003200000_p1_6_w04_s03cd_catalog_drafts.sql` adds
`direct_entry_input_catalog` and `direct_entry_list_own_drafts`, and replaces
`direct_entry_update_draft_row` with a version that merges the submitted worker
display name rather than overwriting hidden optional worker fields.

The server-only write repository calls the catalog, own-draft, update, create,
and restricted-read RPCs; it performs no direct table reads or writes. New
catalog and drafts endpoints reuse the S03A/S03B actor/session boundary. The
existing create API now checks each row against the trusted effective-date
project/recruiter catalog before calling the create RPC. Provider and team are
derived from effective recruiter master data. The draft list is capped at 500;
an excess is reported as `413 DRAFT_LIMIT_EXCEEDED`, not silently truncated.

The live route loads the authorized catalog and own drafts, uses persisted
entry IDs as stable row keys, creates new rows through the existing batch API,
and updates owned draft rows through the existing PATCH endpoint. Errors keep
local edits visible. Writes use idempotency keys; a key is reused only for an
unchanged payload. Stale-version `409` responses fetch the latest restricted
projection and offer explicit choices to apply the server copy or keep the
local copy; neither path silently merges or retries a write.

The demo mode remains synthetic and does not call `/api/direct-entry`. It
states that data is synthetic, unsaved changes can be lost on reload, and the
local “Lưu nháp” action is not a server save.
