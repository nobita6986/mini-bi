## What's in the cutover plan

### 1. Architecture baseline (§2)

Khóa 4 lớp defense-in-depth:

| Layer | Vai trò | Công nghệ |
|---|---|---|
| L1 — Network/proxy | Coarse auth + feature gate | `src/proxy.ts` Basic Auth (slice 7 retirement) |
| L2 — Route/RSC | Session + exact capability check | `@supabase/ssr` + `auth.getUser()` + `getDirectEntryActor` + `resolveActor()` |
| L3 — Server repo | Service-role narrow RPC | `createDirectEntryActorRepository` + RPC-only |
| L4 — DB (PostgreSQL) | Authority cuối (scope/version/idempotency/OCC) | RLS forced + table DML revoked + `SECURITY DEFINER` RPCs |

> **Nguyên tắc vàng:** mọi client field `actor_id`, `role`, `capability`, `scope`, `created_by_user_id`, `owner_user_id` bị reject ở route handler theo W02 adapter rule. DB không bao giờ tin client authority fields.

### 2. Capability vocab + 3-way split (§2.3 + §2.4)

Khóa 29 capability từ auth contract W02, gắn `id_t:capability` duy nhất. Three-way split **không được collapse**:

| Capability | Self-review | Reason/version/audit | Authority |
|---|---|---|---|
| `change_review` | **YES, second-party** (proposer ≠ reviewer) | YES | DB (W03 RPC) |
| `entry_privileged_edit` | NO (single-step) | YES | DB (W03 RPC) |
| `ai.report.review` | **PENDING_DECISION** (T0) | YES (OCC + actor/cursor ở G5 RPC) | Route layer (`api:006`) + DB |

### 5. Library policy (§5)

- Bắt buộc dùng (đã có trong repo): `@supabase/ssr`, `next@16.3.8`, `react@19.2.8`, `radix-ui`, `lucide-react`, `react-data-grid@7.0.0-beta.61`, `zod`.
- Không thêm khi chưa cần: auth framework mới, state library, form library, capability engine bên thứ ba, custom focus trap/dialog/menu.
- Reuse constraint: dùng `src/lib/auth/direct-entry-session.ts`, `src/lib/direct-entry/actor-context-repository.ts`, `src/lib/auth/direct-entry-v2.ts`, audit envelope ở W03, UI components W04-S01/S02.

### 6. AI self-approval (§6)

`PENDING_DECISION` với 2 option + recommendation.

- **Option A** (recommendation): cấm self-approval cho AI; check `actor_ref(job.actor_ref) ≠ actor_ref(reviewer)` ở route `api:006`. Effort: thêm ~10 dòng ở route; OCC + actor/cursor đã có ở G5. Pilot hiện tại sẽ fail vì 1 actor, nhưng prod semantic đồng nhất với direct-entry `change_review`.
- **Option B**: cho phép self-approval; route chỉ check capability. Effort: zero. Mất: audit semantic không đồng nhất.

> **Quyết định cuối: T0.** Tài liệu này **không tự quyết**.

## 3-agent split boundary (for P3 implementation)

Sau khi P1.5/P1.6 integration ổn định + W04-S03C/S03D commit, có thể chia 3 agent theo slice group:

| Agent | Slice | Boundary | Phụ thuộc |
|---|---|---|---|
| **P3A — Auth + Session** | 1 + 2 | Login / logout / callback / cookie refresh; actor bootstrap (`direct_entry_resolve_actor_context` integration) | Không |
| **P3B — Capability + Guard** | 3 + 4 | Page/API guard per ma trận §3.1 + §3.2; App Nav filter server-side; thay `PILOT_ACTOR_REF` ở server repos | P3A cung cấp resolved actor |
| **P3C — Audit + Admin + Cutover** | 5 + 6 + 7 | Audit envelope enforcement; admin/bootstrap user; Basic Auth retirement | P3B cung cấp capability decision |

> **Hard rule.** Không agent nào tự mở capability vocab mới. Nếu cần capability chưa có, escalate T0.
