## Delivered boundary

The live Direct Entry drawer now has an optional document section for CCCD
front/back and employment contracts. It uses a native file input, displays
per-type completeness when `document_view` permits the projection, and shows
version, size, upload/scan state, errors, conflict, and retry status. Replacing
a file creates a new idempotent request and relies on the existing append-only
document version lineage. The synthetic demo remains offline and does not
render or call the live document editor.

`POST /api/direct-entry/entries/[entryId]/documents`:

1. Checks the existing feature gate, UUID, same-origin boundary,
   `Idempotency-Key`, and a bounded multipart body.
2. Rejects unsupported fields and client authority fields. Validates the W01
   document type, MIME allowlist, 10 MiB ceiling, and JPEG/PNG/PDF signatures.
   It calculates SHA-256 on the server and ignores the browser filename.
3. Resolves the existing Supabase session and trusted actor, checks the
   `document_upload` capability, and reads the entry through the existing
   restricted projection.
4. Fails with `DOCUMENT_STORAGE_UNAVAILABLE` before reservation when the
   production adapter is unavailable. A mock adapter can exercise the
   server-only reservation/upload contract in tests.

The production adapter is intentionally unavailable: it makes no network or
Drive calls, and it does not expose credentials. No `READY` or `CLEAN` state
is written from a client request. An acknowledged test adapter returns only a
durable object version plus matching document/version/key/checksum; the API
reports `QUEUED` with a callback pending, never `READY`.

## Migration and RPC delta

No applied migration was edited. The forward-only migration
`20261003230000_p1_6_w04_s04b_document_reservation_adapter.sql` adds one
service-role-only RPC wrapper around the existing
`direct_entry_create_document_metadata` operation. The wrapper returns the
database-generated opaque storage key to the trusted server repository only;
the key is excluded from API responses and client projections. It does not
grant table access or add tables, event transitions, or callback behavior.

The DB-aware dry-run was read-only: all 26 existing migration checksums
matched, with this migration as the sole pending migration. It was not applied
to DEV or PROD. The PGlite acceptance applies the wrapper to a disposable
synthetic database and verifies the 21-function service-role inventory, denied
`anon`/`authenticated` execution, opaque key shape, same-key replay,
changed-payload conflict, and single document/event/revision/audit counts.

## Storage adapter handoff

The current server-only adapter request contains the opaque entry reference,
document ID/type/version, database-generated storage key, checksum, byte size,
MIME type, idempotency key, and validated bytes. A durable worker result must
correlate the exact document ID/version/storage key and checksum and provide
an opaque object version. It must not contain a public URL or user-supplied
filename. S04B-S02 must authenticate the worker callback, apply the existing
event RPC with OCC/idempotency, and progress through quarantine and scan
states before any `READY`/`CLEAN` projection.

| Approach | Trade-off |
|---|---|
| Web-server direct adapter | Fewer hops, but puts storage credentials and large-file transfer/retry behavior in the web tier; no live adapter or credential was added here. |
| n8n/trusted worker | Separates durable upload, scanning, retries, and callback identity from the browser and can reuse an already approved Drive credential if one exists. |

**Recommendation:** use the existing n8n/trusted-worker path if its Drive
credential is approved and reusable. Do not create a second integration or
new credential in S04B-S02; if no reusable worker credential exists, stop for
an explicit architecture/credential decision before enabling storage.
