## 4. CTA enable/disable matrix

CTA (`data-testid="profile-submit"`) bị **disable** khi tồn tại bất kỳ blocker nào:

| Blocker | Điều kiện |
| --- | --- |
| `PROFILE_PREVIEW_EMPTY` | không có preview hoặc 0 dòng |
| `PROFILE_PREVIEW_INVALID` | `errorCount > 0` / `canProceed === false` (unknown–duplicate–missing header, required field sai, ngày sai, CCCD sai, ghi chú vượt 4000, giới tính lạ, …) |
| `PROFILE_CATALOG_UNRESOLVED` | project/recruiter chưa resolve được (missing/ambiguous) hoặc bank chưa resolve khi có payment |
| `PROFILE_PAYMENT_BANK_REQUIRED` | có dòng khai báo payment nhưng `bank_id === null` (bao gồm trường hợp danh mục ngân hàng rỗng) |
| `PROFILE_ROW_LIMIT` | `totalRows > 100` |
| `PROFILE_BODY_LIMIT` | payload vượt 4 MiB |
| `PROFILE_CAPABILITY_MISSING` | thiếu capability mà RPC yêu cầu (§2) |
| `PROFILE_SUBMITTING` | đang gửi |

Blocker hiển thị dưới dạng danh sách tiếng Việt (`data-testid="profile-blockers"`). Nút cũng bị chặn
ở hai lớp nữa: `inFlight` ref + `submitting` state (chống double submit), và `submit()` tự tính lại
blocker trước khi gửi.

## 5. Field/header policy và catalog

- Header-based, thứ tự cột tuỳ ý, không cố định số cột; cột tuỳ chọn có thể vắng (giữ nguyên hợp đồng
  `worker-profile/1.0` của R3A).
- Canonical UI label luôn là **`Mã NLĐ`**; `Mã số ứng viên` chỉ là alias import và **không** xuất hiện
  trên UI (có test browser kiểm tra `document.body.innerText` không chứa chuỗi này).
- Không rơi field nào: `general_note` (entry-level), `worker.gender / date_of_birth / national_id /
  national_id_issued_at / national_id_issued_place / address / phone`, `payment`, `employment` đều được map.
- `national_id` là string 9/12 chữ số, giữ số 0 đầu, không checksum.
- Gender vocabulary D11 (`MALE` / `FEMALE` / `OTHER`) qua alias Nam / Nữ / Khác.
- Cột dẫn xuất (STT / Tháng / Tuổi / Chi nhánh-Team / HRP-Vendor) vẫn **validation-only**, không vào request
  (có test kiểm tra theo key).
- Catalog resolve sang **stable ID** trước khi gửi: `project_id`, `recruiter_id`, `bank_id`.
  **Team/provider không được gửi** — server tự resolve theo D6; gửi sẽ bị `CLIENT_AUTHORITY_FIELD_FORBIDDEN`.
- Không gửi actor/role/capability/scope/auth subject/app user (test theo key set của body thật).

## 6. banks = 0

- Batch **không** mang payment (`payment: null`) vẫn lưu được ⇒ không tắt tính năng paste chỉ vì danh mục
  ngân hàng rỗng.
- Payment ở trạng thái `provided` cần bank `active` ⇒ preview **fail closed** ngay
  (`PROFILE_PAYMENT_BANK_REQUIRED`), không gọi server.
- Mixed batch có một dòng payment-bearing không hợp lệ ⇒ **chặn cả nhóm** (atomic).
- Không bootstrap/hard-code bank ở client; không tự chuyển tên ngân hàng thành ID.

## 7. Idempotency / OCC / retry

- Tái sử dụng `resolveIntentKey` / `clearIntentKey` hiện có — **không** tạo hệ thống key thứ hai.
- Intent = `"full_profile_batch:" + SHA-256(normalized request)`. Digest chỉ là hex; **không** chứa họ tên,
  CCCD, địa chỉ, điện thoại, số tài khoản hay note; key chỉ nằm trong memory của trang (không persist).
- Cùng intent sau network/5xx/unknown ⇒ dùng lại cùng key (“Thử lại”).
- Sửa bất kỳ cell/dữ liệu ⇒ `handleTextChange` kết thúc intent ⇒ key mới.
- Success ⇒ intent kết thúc; lần lưu sau dùng key mới.
- 409 ⇒ **không** auto-retry, xoá key, thông báo sanitized, parent reload/reconcile.
- 400/401/403/404 ⇒ thông báo tiếng Việt đã làm sạch, không lộ mã thô.
- 5xx/network ⇒ không auto-loop, người dùng bấm “Thử lại” với cùng key.
- 2xx nhưng projection không đọc được ⇒ coi là **kết quả không xác định**, giữ key, không tự gửi lại.
- Busy ⇒ CTA disabled + `aria-busy="true"` + `inFlight` ref.

## 8. CCCD/document boundary

- Batch full-profile **không** mang bytes/base64/checksum/storage key.
- Sau success, parent gọi `reloadDrafts()` ⇒ dòng mới đến từ server (kèm `entry_id`), CCCD manager của
  R3A tự bật entry point; **không** giả `0/2` — nhãn vẫn là `Chưa tải trạng thái` cho tới khi người dùng mở
  đúng dòng đó.
- Dòng chưa có `entry_id` ⇒ nút quản lý hồ sơ disabled (hành vi R3A giữ nguyên).
- Reserve → signed PUT → finalize vẫn là boundary riêng; không gọi R2 trong acceptance.
- DOCUMENT change request vẫn scope-lock/read-only như cũ (không chạm).
