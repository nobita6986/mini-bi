- Eligibility and boundaries: a subject must be an active recruiter with a canonical effective HRP provider membership (provider_type 'hrp', vendor_id null); Vendor recruiters, missing/expired/not-yet-effective provider memberships and inactive recruiters fail closed with P0002. - Semantics: assign opens one interval; move closes the outgoing interval and opens the incoming one on the same date inside one transaction (a same-day move leaves the outgoing as a marker); unassign only closes (closing on the interval start writes a marker); future dates are allowed and grant no authority before they start; an inactive team rejects new assign/move while existing memberships stay readable and closable; nothing is hard-deleted, re-dated or merged. A back-dated change that would change the team resolved for a business date already used by an existing direct_entry is rejected with 23514 and the stored entry is never rewritten; an allowed back-dated change records "backdated" in the bounded changed_fields.
- Authority, OCC, revision, audit, idempotency: every read and mutation reuses the single direct_entry_assert_catalog_operator guard (Full Admin triple OR catalog_master_manage, both at effective all scope); no second guard exists. Audit records the real authority (entry_admin or catalog_master_manage, scope_kind all, scope_team_id NULL). Each mutation is one transaction: guard -> validate -> idempotency begin -> lock the recruiters row FOR UPDATE -> expected-version check (40001) -> target validation -> attribution guard -> interval write -> exactly one version bump -> one immutable direct_entry_team_membership_revisions row (fixed six-key snapshot: recruiter_id, team_id, valid_from, valid_to, version, change) -> one audit event linked to that revision -> idempotency finish. Any failure unwinds all of it (zero residue), and reads return the recruiter aggregate version so a client can send it back.

## RPC and API map
- GET /api/admin/catalog/team-memberships?state=current|scheduled|history maps to direct_entry_list_team_membership_current|_scheduled|_history (three disjoint bounded reads).
- POST /api/admin/catalog/personnel/[recruiterId]/team-memberships/[teamId] -> direct_entry_assign_team_membership; .../[teamId]/move -> direct_entry_move_team_membership; .../unassign -> direct_entry_unassign_team_membership. The target team is a resource id taken from the PATH, never the body (the shared client-authority validator rejects client-supplied team fields), and a malformed path id is refused before the session is touched.
