## Safe reviewer scope

- Reviewer CTA is shown only for `PENDING && can_decide === true`. `can_decide` and `can_withdraw` are display hints; server/RPC remain the authority.
- A request is decision-eligible only when every item is `ENTRY_FIELD`, its proposal has a non-empty subset of the five allowed fields (`project_id`, `first_work_date`, `employee_code`, `recruiter_id`, `labor_type`), every entry passes strict projection, all catalog IDs resolve, and each item's `expected_version` matches the projected entry version.
- Unsupported kinds, mixed requests, unknown proposal keys (including `worker_details`), malformed/incomplete entries, catalog mismatches and stale versions fail closed. Unsupported content receives only a generic label; no decision controls or proposal details are shown.
- Before/after view contains only changed allowlisted fields. No raw JSON or PII/payment/document/checksum data is rendered.
- Approve/reject reason is trimmed and required (1..4000 characters). Decision POST uses `/api/direct-entry/change-requests/{requestId}/decision`, the exact contract body `{decision, expected_version, reason, idempotency_key}`, and matching `Idempotency-Key` header.
- Same-intent retry reuses the key; changing decision or reason creates a new key. A 409 does not auto-retry and reloads detail, entry projections and list. 403 and 5xx messages are sanitized. UI state is reconciled only after a valid server response; no optimistic decision.
