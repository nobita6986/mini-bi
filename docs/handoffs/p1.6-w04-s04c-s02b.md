**List item** (đúng 8 key, không thừa/không thiếu):

| Field | Kiểu | Ghi chú |
| --- | --- | --- |
| request_id | uuid | |

| version | int ≥ 1 | |
| created_at | chuỗi ISO UTC `YYYY-MM-DDTHH:MM:SS.uuuuuuZ` | sinh bằng `to_char(... at time zone 'UTC')`, không phụ thuộc TimeZone phiên |

**Detail** (đúng 7 key) + `items[]` đúng 4 key: `entry_id`, `target_kind`, `expected_version`, `proposal`. `proposal` bị kiểm lại theo đúng vocabulary W01/W03 đã khóa (tái sử dụng `projectChangeRequestProposal` của S02A).

**Quyết định đã ghi rõ:**

- **Không trả `reason`/`reason_id`** ở slice này (chưa cần cho UI list/detail). Free-text reason chỉ nằm trong `direct_entry_restricted_reasons` và không có đường đọc nào ở boundary này.
- **Không trả** auth_subject, app_user_id, proposer/reviewer identity, audit envelope, idempotency key/hash, revision, payment/document/PII payload, DB error/message.
- Client không tự khai `state`, `version`, `can_withdraw`, `can_decide`, `created_at`.
- Projection từ chối `can_withdraw === true && can_decide === true` (bất khả thi theo rule audience) và từ chối giá trị bị ép kiểu (`0`, `1`, `"false"`) — không fallback `[]`/`false`/`0`.

## 4. Capability / scope rules (DB là authority duy nhất)

| Trường hợp | Audience | can_withdraw | can_decide |
| --- | --- | --- | --- |
| actor = proposer, có `change_request_create`, và có scope (own/team/all) với **mọi** item | PROPOSER | true khi state = PENDING | **false** (proposer không tự review) |
| actor ≠ proposer, có `change_review`, và có scope với **mọi** item | REVIEWER | false | true khi state = PENDING |
| thiếu capability, hoặc thiếu scope ở **bất kỳ** item, hoặc request 0 item | NONE | false | false |

- Request nhiều entry **fail-closed**: chỉ cần một item ngoài scope là cả request biến mất khỏi list và detail trả not-found (đã kiểm: reviewer team scope không thấy request 2 entry có 1 entry ở team khác).
- Actor không có capability nào liên quan ⇒ list rỗng (không lỗi, không enumeration).
- `direct_entry_has_entry_access` mirror đúng `direct_entry_assert_entry_access`: nếu có **nhiều hơn một** scope grant khớp (ví dụ vừa own vừa team) thì coi như bị từ chối.
- Application **không** đọc trước DB và **không** tự đánh giá capability/scope; không có authority thứ hai, không TOCTOU.

## 5. Keyset pagination (không offset)

- `page_size`: 1..50, mặc định 20; text phải khớp `^[1-9][0-9]{0,2}$` (từ chối `0`, `020`, `1.5`, `abc`, chuỗi rỗng).
- Thứ tự cố định: `created_at DESC, request_id DESC` (tổng, không trùng).
- Cursor opaque do DB sinh: `<yyyyMMddHH24MISSUS UTC>:<request_id>`; client chỉ truyền lại nguyên văn. Sai định dạng ⇒ 22023.
- So sánh keyset bằng tuple text `(stamp, request_id)` — không dùng offset, không dùng `created_at` float.
- `has_more` = có nhiều hơn `page_size` dòng; `next_cursor` chỉ khác null khi `has_more = true` (projection từ chối cặp giá trị mâu thuẫn).
- Lọc `state` chỉ nhận 4 giá trị vocabulary; tham số khác (`order`, `offset`, `limit`, `column`, `sql`…) bị từ chối ở tầng API (400) — client không điều khiển được SQL/order.
- Bằng chứng: walk `page_size=2` qua toàn bộ 6 request cho đúng thứ tự của list đầy đủ, không trùng, không sót, cursor cuối = null; hai request cùng `created_at` được phân định bằng `request_id DESC`.

## 6. HTTP semantics

| Tình huống | HTTP | Code |
| --- | --- | --- |
| Gate tắt | 404 | NOT_FOUND |
| Query sai (page_size/cursor/state/tham số lạ) hoặc có query trên detail | 400 | CHANGE_REQUEST_QUERY_INVALID |
| requestId không phải uuid | 400 | CHANGE_REQUEST_ID_INVALID |
| Chưa đăng nhập | 401 | UNAUTHENTICATED |
| Actor thiếu/malformed/disabled | 403 | ACTOR_NOT_AVAILABLE |
| Mapping/capability/scope denied ở RPC | 403 | CHANGE_REQUEST_DENIED |
| Không tồn tại **hoặc** không nhìn thấy | 404 | CHANGE_REQUEST_NOT_FOUND |
| RPC lỗi khác / projection malformed / throw | 500 | CHANGE_REQUEST_UNAVAILABLE |

Mọi response thành công có `Cache-Control: private, no-store`. Không log payload/reason/PII; không trả raw Supabase error.
