## UI behavior and remaining boundary

The integrated full-profile paste flow treats account number, bank name and
account holder as independent optional metadata. It preserves leading zeroes
and Unicode, does not require or resolve the bank catalog, and never sends
`bank_id`. Empty metadata is `payment: null`; the server accepts it as omitted.
Existing payment capability checks, account masking, audit and revision
redaction remain in force.

The legacy payment editor and `direct_entry_update_payment` RPC remain
unchanged and catalog-based. There is not yet a supported UI path to edit
banking text after an entry has been saved. T1A-PAY-1 is required before
Production UI activation/J01. This integration does not claim that edit path
is complete.

The R4-S02 interactive browser component acceptance was rerun on the
integrated tree with synthetic data and actual components: **67/67 PASS**,
zero failed checks, zero browser console errors, and no Next server error.
Desktop, mobile, partial/full metadata, leading-zero, validation and success
screenshots are retained under `docs/acceptance/p1.6-i04c3-r4-s02/`. The
temporary route, dev route cache and uniquely named Chrome profile were
