Notes:

- Every response carried `Content-Type: application/json` and
  `Cache-Control: private, no-store`, and none carried a Basic Auth challenge, which
  confirms the requests were served past the edge gate on an authenticated session.
- The redaction scan tested each raw response for `auth_subject`, access/refresh
  tokens, JWT markers, `service_role`, Supabase host names, R2 credential names,
  `storage_key`, `checksum`, signed-URL markers, password markers, email-shaped
  strings and database URLs. **No marker matched any response.**
- `app_user_id` is part of the sanctioned actor projection contract, not a leak. Its
  value is deliberately not recorded here.
- `banks[0]` is the expected current state and is **not** treated as a blocker by this
  checkpoint.
- The catalog projection is actor-scoped and effective-date-scoped, so its project and
  recruiter counts describe the requesting actor's authorized view for the requested
  date rather than the total applied catalog.
- The catalog route returns `404` unless `DIRECT_ENTRY_API_ENABLED` is exactly
  `"true"`, and it also rejected an unauthenticated actor with `401` during the
  preceding I05 smoke. The authenticated `200` above is therefore live evidence that
  the API flag is enabled, in addition to the presence-only inspection.

No create, update, transition, upload, download, full-profile batch or R2 operation was
