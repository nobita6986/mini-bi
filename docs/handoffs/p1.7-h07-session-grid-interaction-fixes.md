## A. Không hiện lỗi giả trong lúc session khởi động

### Nguyên nhân

`src/app/direct-entry/page.tsx` (và `src/app/dashboard/page.tsx`) gọi `getDirectEntryActor()` trong SSR. Nếu `getUser()` của Supabase SSR client throw một lỗi transient (network/cookies stream/IMPORT timeout), khối `try/catch` của page-level chỉ fallback `actor = null` rồi `decideDirectEntryPageAccess` trả về `"TEMPORARY_UNAVAILABLE"` → render `TemporaryUnavailable` (tiêu đề "Hệ thống xác thực tạm thời không khả dụng"). User refresh thì lần sau `getUser()` không còn throw → trang vào bình thường. Đây chính là bug A.

### Fix

Thêm bounded retry 1 lần cho transient SSR errors. Không polling vô hạn, không thay đổi contract `getDirectEntryActor`, không thêm dependency.

- Helper mới: `src/lib/auth/direct-entry-session-retry.ts`
  - `resolveSessionWithBoundedRetry(resolve)` chạy `resolve()` tối đa 2 lần, cách nhau 80 ms.
  - Lần đầu throw → retry 1 lần; lần thứ hai vẫn throw → throw tiếp (để caller xử lý).
  - Không retry khi `resolve()` trả về `{ ok: false, reason: ... }` (đó là kết quả 4xx, không phải transient).

- Áp dụng trong `src/app/direct-entry/page.tsx` và `src/app/dashboard/page.tsx`:

  ```ts
  try {
    const session = await resolveSessionWithBoundedRetry(() =>
      getDirectEntryActor(createDirectEntryActorRepository()));
    actor = session.actor;
  } catch {
    actor = null;
  }
  ```

### Tests

- `src/lib/auth/direct-entry-session-retry.test.mjs` (5/5 pass):
  - lần đầu success → không retry;
  - lần đầu throw, lần 2 success → retry 1 lần, trả về kết quả;
  - cả 2 lần throw → throw và `calls === 2`;
  - không retry vô hạn;
  - `UNAUTHENTICATED` (không throw) không bị retry.

- Regression `src/components/direct-entry/direct-entry-h07-session-grid-ux.test.mjs` A1–A3.

## C. Chỉ hiện lỗi thiếu trường bắt buộc sau khi bấm lưu

### Nguyên nhân

`stagedValidation.cellIssues` (từ `buildSpreadsheetValidation`) chứa tất cả issue — bao gồm `PASTE_VALUE_REQUIRED` (required missing) và `PASTE_CATALOG_MISSING` (format/catalog) — ngay khi user gõ. UI (DataGrid + mobile staged list) hiển thị tất cả issues, kể cả các dòng blank dự phòng mặc dù validation đã filter blank.

Note: validation đã filter blank rows (`dataRows = rows.filter(r => !spreadsheetRowIsBlank(r))` trong `direct-entry-grid-validation.ts`). Nhưng khi user gõ 1 phần (e.g. chỉ tên, thiếu ngày), validation chạy → `PASTE_VALUE_REQUIRED` issue xuất hiện ngay từ khi gõ.

Nút save cũng bị disable theo `!stagedValidation.canSave` → user không bấm được để thấy nguyên nhân.

### Fix

- Thêm `stagedValidationTriggered: boolean` state (mặc định `false`) và `quickValidationTriggeredFor: string | null` (mặc định `null`).
- Memo mới `stagedValidationForDisplay`: nếu chưa triggered, lọc bỏ `PASTE_VALUE_REQUIRED` khỏi `cellIssues` (giữ nguyên format/catalog issues). Sau khi user bấm "Lưu các dòng hợp lệ" → set `stagedValidationTriggered(true)` → `stagedValidationForDisplay === stagedValidation`.
- Nút "Lưu các dòng hợp lệ" đổi `disabled` từ `!stagedValidation.canSave || stagedBusy` thành `loadState !== "ready" || stagedBusy`. User luôn click được để kích hoạt required validation. Khi validation fail, hiển thị message "Chưa có dòng hợp lệ để lưu." và ô lỗi sẽ tô đỏ (vì triggered).
- "Lưu NLĐ" (quick editor): set `quickValidationTriggeredFor(target.clientRowId)` trước khi validate. Quick editor render list required errors của row đang mở (CSS class `quickErrorList` mới) khi `quickValidationTriggeredFor === target.clientRowId`. Khi user sửa cell và required value quay lại, error tự biến mất (vì `stagedValidation.cellIssues` không còn chứa `PASTE_VALUE_REQUIRED` cho cell đó).
- Reset `stagedValidationTriggered(false)` và `quickValidationTriggeredFor(null)` sau khi save thành công.

Không thay đổi pipeline validation P1.6; chỉ thêm lớp filter UI.

### Tests

- H07 C1–C6 (regression): regex check `stagedValidationForDisplay`, `setStagedValidationTriggered`, không còn `!stagedValidation.canSave` trong `disabled` prop.

## D. Giá trị cell không được mất khi click ra ngoài

### Nguyên nhân

`react-data-grid@7.0.0-beta.61` có `renderTextEditor` mặc định:

```ts
function renderTextEditor({ row, column, onRowChange, onClose }) {
  return <input
    value={row[column.key]}
    onChange={(event) => onRowChange({ ...row, [column.key]: event.target.value })}
    onBlur={() => onClose(true, false)}
  />;
}
```

Row model của P1.7-W02 đặt giá trị trong `row.cells[column.key]` (object con) và `row.providerType` (trường riêng), **không phải** `row[column.key]`. Mặc định này không tương thích:

- `row[column.key]` luôn là `undefined` → `<input value={undefined}>` = rỗng.
- `onChange` ghi vào `row[column.key]` (cùng key) → row object được Grid lưu vào local `next` array nhưng `onRowsChange` callback (H07) so sánh `row.cells[key]` với `current.cells[key]` (xem line ~325 trước H07): diff bằng 0 → `onCellsChange` không được gọi.
- Kết quả: user gõ, click ra ngoài → `onClose(true)` commit row object đã thay đổi → React rerender với rows mới → nhưng vì `row.cells[key]` không đổi, `renderCell` lại hiển thị giá trị cũ.

Đây là bug D.

### Fix

Tạo `cellsTextEditor` cục bộ trong `direct-entry-spreadsheet-grid.tsx` thay thế `renderTextEditor` cho data columns:

```ts
function cellsTextEditor({ row, column, onRowChange, onClose }) {
  const value = row.cells[column.key] ?? "";
  return (
    <input
      className="rdg-text-editor"
      ref={(node) => { if (node) { node.focus(); node.select(); } }}
      value={value}
      onChange={(event) => onRowChange({
        ...row,
        cells: { ...row.cells, [column.key]: event.target.value },
      })}
      onBlur={() => onClose(true, false)}
    />
  );
}
```

- Commit thông qua `onRowChange({...row, cells: {...row.cells, [column.key]: value}}, /*commitChanges*/ undefined)` (vì `commitChanges` mặc định là `false` — Grid tự merge vào `rows` rồi gọi `onRowsChange` ngay khi user gõ từng keystroke).
- `onBlur` → `onClose(true, false)` ép commit (kể cả khi chưa commitChanges trước đó).
- `Enter` / `Tab` đã được Grid xử lý mặc định qua `onClose`.
- Dropdown (`SelectCellEditor`) đã commit `commitChanges=true` đúng từ trước; `DateCellEditor` cũng đã đúng. Không sửa 2 editor này.

Áp dụng trong `columns` build:

```ts
return {
  ...,
  renderEditCell: cellsTextEditor,  // thay vì renderTextEditor
};
```

Đồng thời bỏ `renderTextEditor` khỏi import từ `react-data-grid`.

Không regress paste Excel (vẫn dùng `onCellPaste`/`onCellCopy`/`onCellKeyDown` cũ) và import XLSX (vẫn chạy `onStagedPaste` qua `onPasteApplied`).

### Tests

- H07 D1–D4 (regression): regex check `cellsTextEditor`, `row.cells[column.key]`, `onRowChange({..., cells: ...})`, không còn `renderTextEditor` trong import.

## E. Làm cho "Chọn một dòng để thao tác" thực sự sử dụng được

### Nguyên nhân

H06 đã có `selectedRows={new Set([selectedClientRowId])}` + `onSelectedRowsChange` để đồng bộ selection. Tuy nhiên, react-data-grid chỉ emit `onSelectedRowsChange` khi checkbox selection đổi, không phải khi user click cell / di chuyển active cell. Kết quả: `selectedClientRowId` luôn `null`, action bar luôn hiển thị "Chọn một dòng để thao tác".

### Fix

- `direct-entry-spreadsheet-grid.tsx`:
  - Thêm `onCellClick` handler:

    ```ts
    const onCellClick = useCallback((args) => {
      if (args.row && args.row.clientRowId !== selectedClientRowId) {
        onSelectedClientRowChange(args.row.clientRowId);
      }
    }, [onSelectedClientRowChange, selectedClientRowId]);
    ```

  - Mở rộng `onCellKeyDown` để cập nhật selection khi nhấn phím điều hướng (mũi tên, Tab, Enter, Home, End, PageUp, PageDown) trong `mode === "ACTIVE"`:

    ```ts
    if (args.row && args.row.clientRowId !== selectedClientRowId) {
      const navigationKeys = new Set([
        "ArrowUp", "ArrowDown", "ArrowLeft", "ArrowRight",
        "Tab", "Enter", "Home", "End", "PageUp", "PageDown",
      ]);
      if (navigationKeys.has(event.key)) {
        onSelectedClientRowChange(args.row.clientRowId);
      }
    }
    ```

  - Truyền `onCellClick={onCellClick}` và `rowClass={...}` cho `<DataGrid>`.
  - CSS: thêm class `.rowHighlight` (background `color-mix(in srgb, var(--primary) 10%, transparent)`) trong `direct-entry-spreadsheet-grid.module.css`. Áp dụng khi `row.clientRowId === selectedClientRowId`. API `rowClass` của react-data-grid là chuẩn, không cần custom row component.

- `direct-entry-live.tsx` — Contextual bar (desktop):
  - Đổi text từ `Đang chọn: <tên/mã>` sang `Đang chọn dòng STT {n}` (n = `spreadsheetRows.findIndex + 1`). Khi row là persisted có `employeeCode`, vẫn hiển thị phụ `· Mã NLĐ <code>`.
  - Staged row → nút `Xóa dòng` (đã có từ H06, giữ nguyên).
  - Persisted row → nút `Hồ sơ NLĐ` (đã có từ H06, giữ nguyên). Nút mở `setDocumentsRowId(persisted.rowId)` → `DirectEntryWorkerDocuments` dùng `entry_id` từ persisted row.

- Selection safety: khi row bị xóa/reload, `selectedSpreadsheetRow` trả về `null` (H06 đã có). UI không cố thao tác trên row đã biến mất.

- Không cản trở edit / copy / paste / Tab / Excel import: tất cả handler trên (`onRowsChange`, `onCellPaste`, `onCellCopy`, `onCellKeyDown`) chạy độc lập với `onCellClick` và `onSelectedRowsChange`. Mobile actions (`DirectEntryQuickDrawer` với `onMobileStagedFieldChange` và nút `Lưu NLĐ`) không bị ảnh hưởng.

### Tests

- H07 E1–E6 (regression): regex check `onCellClick`, `onCellKeyDown` navigation, `rowClass`, `"Đang chọn dòng STT"`, `onStagedDelete`, `setDocumentsRowId(persisted.rowId)`.
