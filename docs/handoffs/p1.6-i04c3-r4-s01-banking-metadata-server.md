## Behavior

`worker-profile/1.0` now accepts optional `account_number`, `bank_name`, and
`account_holder_name` text fields in any non-empty combination. Blank-only
metadata normalizes to `payment: { state: "omitted" }`; non-empty provided
metadata is stored as informational payment metadata without requiring a bank
catalog entry. Leading zeroes in account numbers are preserved, and the
TypeScript parser and SQL RPC trim the same ECMAScript whitespace set.

`bank_id` remains optional and keeps its existing foreign key and active-bank
validation. Providing an invalid or inactive legacy bank ID still fails.
Payment reads continue to require `payment_view` for unmasked account data;
unauthorized reads receive a last-four mask and no bank name or account holder.
Revision snapshots and audit events do not contain raw account metadata.

The existing `direct_entry_update_payment` RPC and UI were intentionally not
expanded: this task supports the metadata on full-profile batch creation and
read projection, but does not add a bank-name edit path. Any corresponding UI
work remains a separate task.
