## Synthetic acceptance

All fixtures use random synthetic identities and run inside one transaction that
is unconditionally rolled back. No document bytes or fixture identifiers are
printed. The harness covers:

- Valid scoped draft reservation and fail-closed production storage rejection
  before any reservation.
- Missing file, unsupported document type/MIME, bad magic bytes, >10 MiB,
  nested actor authority, client-selected storage key, forged READY/CLEAN, and
  public URL rejection before mutation.
- Server SHA-256 and opaque database-generated key; the browser filename is
  ignored and is absent from the trusted upload request, response, projection,
  audit, and revision snapshots.
- Same-key/same-payload retry returns the same reservation without a second
  document version, event, revision, audit record, or idempotency result.
- Same-key/changed-payload and stale entry version return stable HTTP 409 with
  no storage retry.
- Replacement appends version 2, links `supersedes_document_id`, and remains
  `QUEUED`/`PENDING`.
- Restricted team projection omits documents without `document_view`; neither
  full nor restricted projection exposes checksum, physical key, filename,
  public URL, or adapter receipt.
- Disabled, unmapped, and out-of-scope actors are denied.
- Injected audit and revision failures roll back document versions, events,
  entry revisions, audit, and idempotency atomically.
