## Architecture (locked)

Preview bucket `hrp-bi-preview`, production bucket `hrp-bi-product`, APAC, private, no public URL or custom domain. JPEG/PNG/PDF only, maximum 10 MiB. No malware scanner and no n8n/Drive/Sheets/Telegram path. The bucket is chosen server-side from `VERCEL_ENV` (`production` → product, otherwise preview); a bucket name that does not match the environment makes the adapter unavailable. The client never sends a bucket, key, status or storage profile.

Official `@aws-sdk/client-s3@3.1146.0` and `@aws-sdk/s3-request-presigner@3.1146.0` (Apache-2.0) are pinned exactly. No hand-written SigV4, no raw `fetch` on the server.

## Protocol

| Step | Route | Behaviour |
| --- | --- | --- |
| Reserve | `POST /api/direct-entry/entries/{entryId}/documents` (JSON, `Idempotency-Key`) | Strict body `{document_type, expected_entry_version, size_bytes, mime_type, reason?}`. Order: flag → ids → origin → JSON → claimed type/MIME/size → session + `document_upload` → storage availability (`503 DOCUMENT_STORAGE_UNAVAILABLE` before any DB call) → DB reservation RPC → presigned PUT only if the document is still `QUEUED`. Response: opaque `document_id`, `version`, `entry_version`, statuses, `upload {method, url, headers, expires_at}`. The URL is never stored or logged. |
| Upload | Browser `PUT` to the signed URL | Signed for the staging key, `Content-Type` and `Content-Length`; lifetime 300 s. |
| Finalize | `POST …/documents/{documentId}/finalize` (`{expected_entry_version}`, `Idempotency-Key`) | Context RPC → HEAD → size/MIME check → bounded GET (≤10 MiB) → server SHA-256 → magic bytes and structural checks → copy to final key → finalize RPC → delete staging. |
| Download | `GET …/documents/{documentId}/download` | Session + `document_view` + scope via context RPC; only eligible documents; 302 to a presigned GET (120 s, `attachment`, generic name such as `cccd-front-v1.pdf`), `Cache-Control: private, no-store`, `Referrer-Policy: no-referrer`. |

Object keys: `<env>/staging/<opaque storage_key>` and `<env>/final/<opaque storage_key>`, where the storage key is the existing DB-generated `p1.6/<candidate_uuid>/<TYPE>/<version>/<document_uuid>`. No filename, CCCD, name or PII appears in keys or metadata.

Finalize failure handling: missing object → `409 DOCUMENT_UPLOAD_MISSING` (no mutation); oversized, size/MIME mismatch or invalid content → staging deleted, a sanitized `FAILED/REJECTED` event is recorded, `422`. DB failure after copy → `503`, staging and final copy are kept for reconciliation, no key is exposed; a retry re-copies (idempotent) and finalizes once, and the RPC idempotency prevents duplicate revisions.

## No-scanner policy

No scan is simulated. The migration records `validation_status = VALIDATED` with `scan_status = NOT_REQUIRED`. A document is current/eligible when `READY`, `VALIDATED` and scan is `CLEAN` or `NOT_REQUIRED`. The UI says “Đã kiểm tra định dạng” and never claims virus scanning or safety. Download is attachment-only; there is no inline preview in this checkpoint.

## Retention contract

Abandoned staging objects are eligible for cleanup after 24 hours; invalid uploads are deleted immediately; accepted versions are never auto-deleted; replacements create a new version and never overwrite an old one; admin purge with audit is a later phase. `classifyStagingObject` and `DOCUMENT_RETENTION` define the contract; no cron or network cleanup exists yet.
