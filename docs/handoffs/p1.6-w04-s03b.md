## Implementation

Added `POST /api/direct-entry/batches` and
`GET /api/direct-entry/entries/[entryId]`. Both endpoints check the exact
server-side `DIRECT_ENTRY_API_ENABLED=true` flag before session or repository
setup and return sanitized 404 responses when disabled. POST reuses
`checkSameOriginRequest`, requires JSON and a bounded 1–128 character
`Idempotency-Key`, caps streamed request bodies at 64 KiB, and rejects nested
client-supplied authority fields. Batch rows are validated with the W01 worker
and employee-code validators and projected to the exact RPC input fields.

Both endpoints reuse `getDirectEntryActor` and
`createDirectEntryActorRepository`; the client supplies no actor, capability,
scope, provider, or team authority. A new server-only repository calls only
`direct_entry_create_batch` and `direct_entry_read_projection`, with actor IDs
from the resolved server context. It has no direct table queries or mutations.
RPC errors map to fixed public error codes; raw database messages are neither
returned nor logged. Entry reads strictly validate and preserve the existing
RPC projection/redaction. Responses use `Cache-Control: private, no-store`.

The current create RPC returns no replay marker, so the API does not synthesize
a `reused` flag. Identical idempotent retries return the same submission and
entry IDs.
