# P1.7-W01B — Spreadsheet row staging

Status: `P1.7-W01B_ROW_STAGING_LOCAL_PASS_FAST_TRACK`

## Scope

Pure client-only row staging for the P1.7 spreadsheet grid. This slice does not render UI,
parse clipboard data, call an API, create server records, or persist PII outside React memory.

## Public API

- `createSpreadsheetRowModel()` creates 30 blank client placeholders.
- `updateSpreadsheetRowCells()` applies raw string cell patches while preserving the row ID.
- `ensureSpreadsheetSpareRows()` keeps 10 blank rows after the last data row.
- `spreadsheetRowIsBlank()` defines blankness from persisted worker-profile fields only.
- `selectNonEmptySpreadsheetRows()` returns save candidates in their visual order.
- `clearSpreadsheetRow()`, `deleteSpreadsheetRow()` and `duplicateSpreadsheetRow()` implement
  unsaved-row actions without server identifiers.
- `SPREADSHEET_WRITABLE_FIELD_KEYS` is derived from persisted `WORKER_PROFILE_FIELDS`, so derived
  columns never make an otherwise empty row eligible for validation or save.
- `SpreadsheetDataRowLimitError` prevents creating a 101st data row. Ten trailing placeholders
  remain client-only and do not count toward the 100-row batch limit.

`clientRowId` uses a monotonic sequence held inside the model. Deleting a row never recycles its ID.
