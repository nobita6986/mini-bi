# P1.7-W03A draft-list projection

## Result

Implemented a versioned, single-request draft-list projection for the spreadsheet grid. The existing `GET /api/direct-entry/drafts` route and `direct_entry_list_own_drafts` RPC remain the read path; the RPC now returns rows accessible through the actor's existing `own`, `team`, or `all` scope. The API still resolves the actor server-side, and the repository strictly projects the RPC payload before returning it.

This is a server/API/DB projection only. It adds no table, mutation path, bank catalog dependency, document metadata, UI component, or production configuration. The new forward-only migration is migration #38:

`supabase/migrations/20261006010000_p1_7_w03a_draft_projection.sql`

## Response contract

`GET /api/direct-entry/drafts` returns the existing row fields plus `profile`, with an explicit top-level projection version:

```ts
type DraftProfileField =
  | { state: "provided"; value: string }
  | { state: "omitted" | "unknown" | "intentionally_blank" }
  | { state: "redacted"; present: boolean };

type DraftPaymentAccountField =
  | DraftProfileField
  | { state: "masked"; value: string };

type DraftProfileProjection = {
  contract_version: "worker-profile/1.0";
  worker_details: {
    display_name: DraftProfileField;
    gender: DraftProfileField;
    date_of_birth: DraftProfileField;
    national_id: DraftProfileField;
    national_id_issued_at: DraftProfileField;
    national_id_issued_place: DraftProfileField;
    address: DraftProfileField;
    phone: DraftProfileField;
  };
  general_note: DraftProfileField;
  employment: null | {
    status: "UNCONFIRMED" | "ON" | "OFF";
    effective_date: string;
    version: number;
    leave_date: DraftProfileField;
    leave_reason_text: DraftProfileField;
  };
  payment: null | {
    state: "provided" | "omitted" | "unknown" | "intentionally_blank" | "not_provided";
    account_number: DraftPaymentAccountField;
    bank_name: DraftProfileField;
    account_holder_name: DraftProfileField;
    version: number;
  };
};

type DraftListResponse = {
  ok: true;
  projection_version: "direct-entry-draft-list/1";
  drafts: Array<{
    submission_id: string;
    submission_version: number;
    entry_id: string;
    entry_version: number;
    employee_code: string;
    first_work_date: string;
    worker_display_name: string;
    project_id: string;
    project_display_name: string;
    recruiter_id: string;
    recruiter_display_name: string;
    provider_type: "hrp" | "vendor";
    team_id: string;
    team_display_name: string;
    labor_type: "TEMPORARY" | "PERMANENT";
    employment_status: "UNCONFIRMED" | "ON" | "OFF" | null;
    created_at: string;
    updated_at: string;
    profile: DraftProfileProjection;
  }>;
};
```

The authoritative TypeScript projection and strict validator are in `src/lib/direct-entry/write-repository.ts`. Unknown keys, malformed field states, duplicate entry IDs, wrong versions, invalid dates, and invalid masked account shapes fail closed.

## Capability and scope rules

| Data | Projection |
| --- | --- |
| Entry IDs/versions, employee code, date, project/recruiter labels and IDs, provider/team, labor type, current employment status | Returned only for entries in the actor's existing scope. Scope is rechecked in the database for each row. |
| Worker fields and `general_note` | Raw values only with `pii_view`. Otherwise field values are replaced with state/presence markers. The legacy `worker_display_name` field remains a string for W02 compatibility and is empty without `pii_view`; use `profile.worker_details.display_name` for the explicit marker/value. |
| Payment account number | Raw value only with `payment_view`; otherwise the existing last-four mask is returned. |
| Bank name and account holder | Values only with `payment_view`; otherwise omitted/redacted markers. `bank_name` remains text metadata; `bank_id` is not projected. |
| Leave date and reason | Values require both `employment_status.apply` and `pii_view`; with apply but without PII access, return redacted markers. Without the existing apply capability, omit the fields. Employment status/effective date/version remain the existing scoped status projection. |
| Documents, storage keys, checksum, bucket, signed URL, idempotency, capability, scope, raw DB row | Not returned. |

The list remains capped at 500 rows and ordered by `created_at, entry_id`, matching the existing endpoint. There was no list pagination contract to change. One RPC call returns the full batch; the SQL resolves latest employment/payment records in the batch query.

## T1A integration

1. After reload, call `GET /api/direct-entry/drafts` once and require `ok === true` and `projection_version === "direct-entry-draft-list/1"`.
2. Keep using the existing core fields for entry ID/version, project/recruiter labels, provider/team, labor type, and current employment status.
3. Hydrate optional worker, note, employment, and payment cells from `draft.profile`; render `redacted`/`masked` states distinctly from empty values. Do not copy masked account values into a write request.
4. Keep STT, age/month and display hints derived in the client. `profile.payment.bank_name` is text; do not resolve it through the bank catalog.
5. Keep any later mutation request on its own existing contract; this projection introduces no write semantics.
