# P1.7-H05 — Direct Entry production UI fixes

## Scope and status

Implemented and locally verified on `feature/p1.7-h05-direct-entry-ui-fixes`, based on
`origin/main@524961e6b515774b88df3cf68f49b46c5437b384`.

This handoff covers the production UI fixes for the Direct Entry spreadsheet:
default grid columns, dropdown editors, project catalog, HRP/Vendor + recruiter wiring,
"Chính thức" labor type label, CCCD action rail moved outside the grid, exact-row
deletion, two distinct add-row buttons, toolbar with five actions, and a 17-header XLSX
template/import path. It does not authorize applying migrations, deploying, changing
shared data, or performing Production UI UAT. It does not claim P1.7 PASS or
Production readiness.

## Changes

### 1. Default grid (18 columns)

`DIRECT_ENTRY_DEFAULT_GRID_COLUMN_KEYS` is now exactly the 18 H05 columns in order:
STT, Dự án, Ngày bắt đầu làm việc, Họ và tên, Giới tính, DOB, CMT/CCCD, Ngày cấp,
Nơi cấp, Địa chỉ, Số điện thoại, HRP/Vendor, Người tuyển / Vendor, Loại hình LĐ, STK,
Tên ngân hàng, Tên chủ tài khoản, Ghi chú. STT is a display ordinal, Mã NLĐ is not
editable on the grid and is server-generated by migration #39 as `hrp-YYYY-NNNNNN`.
Tuổi is derived from DOB; lifecycle columns (Tình trạng, Ngày nghỉ, Lý do nghỉ),
CCCD documents, Team, save status, and row actions do not appear in the default
data-column list.

`DIRECT_ENTRY_GRID_COLUMNS` registry keeps the full 28-column contract set so
drawer/projection/validation and future column toggles still work. The 18 default
keys are the only ones that flow into the data-column array passed to `DataGrid`.

`DIRECT_ENTRY_ACTION_RAIL_COLUMN_KEYS` is now `["save_status", "row_actions"]` —
`cccd_documents` has been removed from the in-grid action rail; CCCD lives outside
the grid (see §7).

### 2. Initial input fields

The 17 data fields (everything except Mã NLĐ, Tuổi, lifecycle) are present on the
default grid AND on the mobile/quick-editor drawer. Giới tính dropdown contains only
`Nam` and `Nữ` (no auto-default), backed by the existing `DIRECT_ENTRY_GENDER_OPTIONS`
constant. STK keeps leading zeros because it is text in the contract (no `numFmt`
coercion in the XLSX template either). Tên ngân hàng is plain text metadata; the
no-op bank catalog from P1.6 is not required.

### 3. Required-field `*` markers

Desktop grid headers, mobile card editor, and quick editor drawer all render a red
`*` next to the six mandatory fields: Dự án, Ngày bắt đầu làm việc, Họ và tên,
HRP/Vendor, Người tuyển / Vendor, Loại hình LĐ. The mark is presentation only —
canonical field names, the XLSX template, validation messages, and CSV/TSV output
do not contain `*`. The required mark is announced to screen readers via
`aria-hidden="true"` plus a `required` flag on the underlying input/select where
the existing editor supports it.

### 4. Dropdown editor and project catalog

`SelectCellEditor` now renders a full-width, full-height native `<select>` with the
caret aligned to the right; the editor matches the cell's box so row height does
not jump on focus. The editor reuses the existing `DIRECT_ENTRY_GENDER_OPTIONS`,
`DIRECT_ENTRY_LABOR_TYPE_OPTIONS`, and `DIRECT_ENTRY_PROVIDER_OPTIONS` constants.
`recruitersForProvider` filters recruiter options by the row's `provider_type`.

The project dropdown resolves the catalog per row using
`row.catalogOptions ?? catalogOptions` and reuses the existing
`ensureCatalog(first_work_date)` mechanism. The project cell renders the project
`display_name` while saving the stable `project_id` to the staged model. Four
states are surfaced as inline text:

- No date: `Nhập ngày bắt đầu trước`
- Loading: `Đang tải danh mục…`
- Load error (sanitized): `Danh mục chưa khả dụng`
- Empty: `Chưa có dự án khả dụng`

A regression test asserts the editor renders a list of multiple projects from a
catalog and selects the matching stable ID.

### 5. HRP/Vendor and recruiter filter

`HRP/Vendor` dropdown contains exactly `HRP` and `Vendor` (no `Chọn nhà cung cấp`
visible). The empty option is only used internally for the controlled select. The
"required *" mark is present on the column header.

`Người tuyển / Vendor` is disabled until `HRP/Vendor` is chosen. When HRP is
selected, the dropdown shows only HRP recruiters; when Vendor is selected, only
Vendors. The selection is cleared when the provider changes. Saved values are
stable catalog IDs; the UI renders labels.

### 6. Labor type label

`Loại hình LĐ` shows `Thời vụ` and `Chính thức` on the desktop grid, the mobile
card, the quick editor drawer, and the XLSX template. The legacy alias
`Toàn thời gian` is accepted on XLSX import and mapped to the canonical
`PERMANENT` server value. The grid, drawer, and template never render
`Toàn thời gian` in the new UI.

### 7. CCCD action rail outside the grid

`Hồ sơ CCCD` is no longer a `react-data-grid` data column. The grid render path
returns `null` for `column.key === "cccd_documents"`; the data-column array only
contains the 18 H05 keys plus `save_status` and `row_actions`. CCCD is rendered as
a fixed right-side action rail in `direct-entry-live.tsx`:

- Staged row: button is `disabled` with `Lưu dòng trước` label/tooltip.
- Persisted row: opens the existing `DirectEntryCccdManager` for that row.
- Document upload reuses `DirectEntryDocumentEditor`, the
  reserve → signed PUT → finalize boundary, OCC, idempotency, and the existing
  capability check (`document_upload`). No new endpoint or transport.
- Mobile: CCCD status appears in each row card and the drawer footer.

The action rail does not participate in `DIRECT_ENTRY_DEFAULT_GRID_COLUMN_KEYS`,
the XLSX template/import, or the paste coordinate mapping, and it never exposes
storage key, checksum, bucket, signed URL, or raw internal metadata.

### 8. Exact-row deletion

The red `×` button in the in-grid action rail only renders for
`row.clientStaged === true` and only fires `onDeleteRow(row.clientRowId)` which
calls the existing `deleteSpreadsheetRow` helper. The button has `aria-label="Xóa
dòng"`, a tooltip, and `event.stopPropagation()`. Persisted rows do not show this
button. There is no DELETE API call, no `clientRowId` reuse, and other rows
(including their IDs and data) are preserved.

### 9. Two add-row buttons

- `Thêm dòng` (toolbar): each click adds exactly 10 blank staged rows in one
  atomic batch (`ensureSpreadsheetRowCount`); the count guard ensures the
  100-data-row limit is not exceeded partially — the button is disabled and an
  inline message (`Đã đạt giới hạn 100 dòng dữ liệu; không thêm được 10 dòng
  mới.`) is shown when there is no room for a full batch.
- `Thêm nhanh NLĐ` (toolbar): reuses the first blank staged row if one exists;
  otherwise creates a new blank row (respecting the 100-row limit) and opens the
  quick editor drawer on that `clientRowId` immediately. The quick form contains
  the same 17 fields as the grid, supports `Lưu NLĐ` (single-row save through the
  existing full-profile batch transport), `Đóng` (keeps staged data), and
  `Xóa dòng` (removes the open row only). The form renders required `*` marks and
  reuses the same catalog/validation/projection as the grid.

### 10. Toolbar

The header now contains exactly five buttons: `Tải file Excel mẫu`,
`Nhập file Excel`, `Thêm dòng`, `Thêm nhanh NLĐ`, `Lưu các dòng hợp lệ`. The
legacy `Dán từ Excel` / `Dán hồ sơ từ Excel` triggers are not rendered; the
parser/helper is preserved for a future clipboard task. The `direct-entry-v1` and
`worker-profile-paste` parsers were not modified.

### 11. XLSX template and import

`worker-profile-xlsx.ts` now produces a 17-header template (Dự án,
Ngày bắt đầu làm việc, Họ và tên, Giới tính, DOB, CMT/CCCD, Ngày cấp, Nơi cấp,
Địa chỉ, Số điện thoại, HRP/Vendor, Người tuyển / Vendor, Loại hình LĐ (rendered
as `Chính thức`), STK, Tên ngân hàng, Tên chủ tài khoản, Ghi chú). The template
has no STT, Mã NLĐ, Tuổi, status, action, or internal fields. STK and CMT/CCCD
columns use `@` (text) format so leading zeros survive. Data validation lists
exist for `Nam/Nữ`, `HRP/Vendor`, and `Thời vụ/Chính thức`. A version marker
`worker-profile-xlsx/1` is stored in the veryHidden `_meta` sheet. The Hướng dẫn
sheet lists which fields are required; no sample PII is included.

Import:
- Limit 100 rows, 4 MiB body size (unchanged).
- Numeric/Formula/Error cells in sensitive columns are rejected with
  `XLSX_CELL_UNSUPPORTED`.
- `Toàn thời gian` is accepted and mapped to canonical `PERMANENT` /
  `Chính thức`; legacy `Mã NLĐ` column at position 1 is dropped, with a column
  offset so the remaining 17 cells map correctly to the H05 data order.
- Issue codes from `worker-profile-import-contract.ts` are mapped to
  row/column indices with sanitized messages.

### 12. Save, validation, persisted row

`buildSpreadsheetValidation` (existing P1.6 pipeline) runs over the staged rows
and surfaces per-cell issues plus a per-row count. Save uses the existing
full-profile batch transport (`postFullProfileBatch`) with idempotency/OCC and
409-no-auto-retry semantics. Blank rows are not validated and not sent. Staged
rows are only removed after the server returns a valid projection for the saved
row. Persisted rows can edit the four optional fields (STK / Tên ngân hàng /
Tên chủ tài khoản / Ghi chú) directly on the grid when the row is in DRAFT and
the actor has the right capability; REVIEW/SUBMITTED rows remain read-only.
