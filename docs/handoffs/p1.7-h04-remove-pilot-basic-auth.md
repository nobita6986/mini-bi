## 2. Route matrix — before and after

| Route | Before (Basic Auth matcher) | After |
| --- | --- | --- |
| `/login` | Basic Auth 401/503, realmer `Mini BI Pilot` | **Public** (Supabase login form renders) |
| `/api/auth/login\|logout\|session` | Basic Auth in front of the auth contract | Same auth contract; same-origin/CSRF logic unchanged; no Basic challenge |
| `/dashboard` | Basic Auth **only** — the page had no session guard at all | **Supabase session required**: `getDirectEntryActor` runs before any reporting read; unauthenticated → `redirect("/login?next=/dashboard")` |
| `/direct-entry` | Basic Auth + page decision | Unchanged page decision (flag + actor + entry capability) |
| `/pipeline-check` | Basic Auth | Server-side redirect to `/dashboard` (no data read); now reaches a guarded dashboard |
| `/api/reporting/*` | In the matcher | **Does not exist in this repo.** Reporting data is read server-side in `/dashboard`, now behind the session guard |
| `/api/ai/reports`, `/capability`, `/history`, `/[jobId]/*` | Basic Auth + feature flag + CSRF | `guardApiSession()` → 401/403 + feature flag + CSRF/origin |
| `/api/ai/settings\|activate\|disable\|rotate\|test` | Basic Auth + `guardSettingsRequest` | `guardApiSession()` before `guardSettingsRequest` (flag, CSRF, rate limit) |
| `/api/ai/worker/run` | Basic Auth + worker token | **Worker token only** — machine-to-machine endpoint; adding a session requirement would break the sanctioned worker |
| `/api/direct-entry/*` | Basic Auth + actor/capability/CSRF | Unchanged actor/capability/CSRF guards; no Basic challenge |

Classification: public — `/login`; Supabase session required — `/dashboard`, AI report read/mutation
routes; enabled actor required — all AI routes and `/api/direct-entry/*`; capability required —
`/direct-entry` page and the Direct Entry APIs; feature flag required — `/direct-entry`
(`DIRECT_ENTRY_UI_ENABLED`), `/pipeline-check` behaviour, and every `/api/ai/*` route.

proxy matcher.

Reused guard: the existing Supabase helpers only — `getDirectEntryActor` +
`createDirectEntryActorRepository`. No new auth framework, capability or migration.

## 4. AI/reporting safety evidence

- Unauthenticated read of AI/reporting data is blocked by `guardApiSession()` returning 401 before
  any provider/config/service call.
- Unauthenticated AI settings reads and mutations are blocked by the same guard, which runs before
  `guardSettingsRequest`.
- Mutations still go through the existing `checkSameOriginRequest` CSRF/origin checks and the
  existing rate limiter.
- Responses carry only `{ ok: false, code }`; no envelope, provider URL or secret is returned.
