## Route and feature gate

`/direct-entry` is force-dynamic and renders only when the server-side
environment variable `DIRECT_ENTRY_UI_ENABLED` is exactly `true`. Missing,
false, and other values fail closed through `notFound()` before the UI is
rendered. The global navigation entry remains planned/hidden. This route was
not deployed.

## UI behavior

Desktop and tablet mount the pinned `react-data-grid@7.0.0-beta.61` with typed
columns and rows, stable synthetic `rowId` keys, and local-only edit callbacks.
The visible fields are employee code, first work date, pseudonymous worker,
project, recruiter, derived read-only HRP/Vendor, employment type, and work
status. Editable text cells use an explicit editor. The fixture contains no
real personal, payment, or document data.

Recruiter options come from the synthetic master fixture. Search reuses the
S01 native Vietnamese-aware helper, keeps stable recruiter IDs as values, and
derives provider/team labels from the selected master record. The grid and
mobile form do not allow manual provider entry.

At mobile widths the grid is hidden and a row list opens a Radix form drawer.
Edits stay in page memory. The UI states that data is synthetic, changes have
not been sent to a server, and reload may discard them. Edited rows have a
dirty indicator; “Lưu nháp” only records a local simulated-save state.

no dependency beyond the already pinned grid package.

  none is implemented in this fixture route.
