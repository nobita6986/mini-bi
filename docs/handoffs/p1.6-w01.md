## Locked decisions

| Topic | Decision |
|---|---|
| Submission | One batch of 1..N unique `entry_id`s, with creator, state, optimistic version and timestamps. Empty/duplicate-entry batches are rejected. REVIEW/SUBMITTED transitions apply to the whole batch; REVIEW may return to DRAFT. |
| First submit | SUBMITTED publishes canonical data immediately without Admin/Accounting approval. Later normal-user edits require change requests. |
| Identity | `app_user_id` on an entry is its creator/actor. Recruiter and candidate remain separate identities. Actor↔recruiter matching requires an explicit verified effective link; no equality/name/email inference. |
| Recruiter/provider/team | At `first_work_date`, require exactly one effective provider membership across HRP/Vendor and one effective team membership. Any overlap rejects, including same-type overlap. Provider type derives from membership; submitted provider value is only a matching assertion. Recruiter/team must be active. |
| Employee code | Strict lowercase `hrp-YYYY-NNNNNN`; six-digit string preserves leading zeros and year matches `first_work_date`. DB is uniqueness/reservation authority; manual entry allowed with atomic server validation. OFF/cancelled codes are never reused. Other numeric widths go to legacy/quarantine, never canonicalized. |
| Employment status | Starts UNCONFIRMED. `effective_date` must be on/after first work and not in the future. OFF requires trimmed reason (≤4,000 chars) and `leave_date === effective_date`; ON/UNCONFIRMED leave fields are null. Corrections append superseding events; only latest active event is correctable. |
| Bank | Optional on initial submission with `omitted`/`unknown`/`intentionally_blank`/`provided`. `provided` requires account number, active bank and holder name. Normal users edit in DRAFT/REVIEW; after submit they see masked values and request changes. Privileged full view/direct edit requires capability, reason, version, revision and audit. Plaintext account values do not go in ordinary audit; legal retention is deferred to P3. |
| Documents | CCCD_FRONT, CCCD_BACK, EMPLOYMENT_CONTRACT are not initial-submit blockers; missing/present completeness is exposed. PDF/JPEG/PNG, max 10 MiB. Replacements append immutable versions. Idempotency scope: candidate ref + document type + idempotency key. Storage key excludes CCCD plaintext and browser filename. |
| Change request | Created only after SUBMITTED; every item has expected version; approval stages all rows and applies atomically, a stale row aborts all. Proposer may withdraw while pending. Reviewer, decision time and reason are recorded without rewriting proposal items. No hard SLA. |
| Grid | GO-WITH-CONDITIONS for `react-data-grid@7.0.0-beta.61`; desktop/tablet grid and mobile row-list + drawer. R1 adds no dependency. |
