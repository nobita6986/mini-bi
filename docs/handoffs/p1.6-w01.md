## Decisions encoded

- `app_user_id`, `recruiter_id`, and `candidate_id` are separate. Only a verified effective-dated explicit user↔recruiter link can suggest a recruiter; absence never infers identity.
- Recruiter and team identity/membership are inherited from P1.5-W02; intervals are half-open. New entries require active recruiter, matching provider and exactly one effective team membership.
- Employee code canonicalizes to lowercase `hrp-YYYY-[1..18 digits]`; string suffix keeps leading zeros; year follows `first_work_date`; duplicates reject and retired codes are never reused. Fixed padding/issuer remains OPEN for T0.
- DRAFT/REVIEW/SUBMITTED and post-submit change request behavior are explicit. Pending changes do not mutate canonical data; approval stages all patches, checks expected versions and applies atomically; rejection leaves values unchanged. Privileged direct edit requires capability, reason, optimistic version, private revision, and audit.
- Payment uses explicit omitted/unknown/intentionally-blank/provided states; account data is a complete optional group and remains a string.
- Employment status starts UNCONFIRMED; only allowed transitions append events. OFF requires date and free text. Corrections append a superseding event; past/future bounds remain OPEN for T0.
- Documents have checksum, idempotency, MIME/size policy, quarantine/scan placeholders, retries and immutable versions. Physical storage name uses candidate ref + document type + opaque document ID + version, never CCCD plaintext.
- Grid decision: GO-WITH-CONDITIONS for `react-data-grid@7.0.0-beta.61` at W04; multi-cell paste is in MVP, rectangular range-copy is not. Benchmarks and limitations are in the contract and linked spike report.
