## Required work

1. Reuse Worker Operations and the existing POST /privileged-edit route/API/repository/RPC. Add the `team` worker-directory scope and consume the server-projected `allowed_actions.direct_edit` row signal. Gate the CTA on that row signal so an authorized Team Leader row is not hidden by a client role/title or a legacy global capability flag. UI visibility is not security: the RPC must authorize each request and deny after revocation.
2. Keep actor identity server-derived. Do not add client-supplied role/title/team IDs as evidence. Do not create a broad all-scope path.
3. Preserve validation and user feedback for all existing patch fields, status values, OFF leave reason, version conflicts, duplicate/idempotency outcomes, and locked submissions. Retain clear loading, error, and retry behavior.
4. Add a Team tab/scope to Worker Operations so a Team Leader can find only their server-authorized current-team rows; do not overload `managed` or `all` to mean team authority. Preserve existing Admin/BoD tabs and access.
5. Reuse the existing change-request queue and detail endpoints/RPCs. Ensure Team Leader A can see/read/decide current team A requests, Leader B cannot access team A, and displayed approve/reject affordances follow server `can_decide` in list and detail.
6. For WORK_STATUS, show the current status and proposed status from the existing safe projection and retain the existing Agree/Reject decision path. Reuse the current reviewer branches; do not rewrite the reviewer or expand DOCUMENT/ENTRY_VOID policy to make status requests work.
7. Load current entry projections for every request item and show accurate before/after values. Preserve current field projection, PII/payment/document guards, stale-state handling, and focus/accessibility behavior.
8. Ensure all failures terminate loading: request/detail/entry 403, 404, 500, network errors, invalid strict projections, unsupported targets, and stale version. Fail closed when a projection is not safe or complete.
9. Support existing persisted kinds ENTRY_FIELD, PAYMENT, WORK_STATUS, DOCUMENT, and ENTRY_VOID only where their existing projection and guards support them. Preserve ENTRY_VOID's current one-item/reviewer policy; do not broaden it while restoring ordinary team review. WORKER is a proposal-form label that maps to ENTRY_FIELD, not a persisted kind; do not add one.
10. Team Leader own proposals may be viewed only under server proposer rules. Never render self-approval based on proposer status or client role. Keep Staff self-review denied.
11. In B-owned UI, make direct-edit, approve/reject, and worker-export action-reason inputs optional per C's early normalization contract. Empty/whitespace should be sent as null or omitted consistently, not rejected by a required HTML field. C owns the separate change-request proposer UI and submission contract. Keep OFF leave_reason required.
12. Do not touch SQL migration files, RLS/grants, database authority, or non-B-owned UI/API modules.
