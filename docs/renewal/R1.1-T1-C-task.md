## Contract behavior

1. At the trusted API boundary, accept absent, null, or blank optional action reason and canonicalize all three to NULL. Trim a nonblank value and retain its existing type and maximum length. Preserve absent-field compatibility for old clients where practical.
2. Do not silently convert malformed types or overlong values to null. Those remain invalid.
3. Do not change employment_status.leave_reason, WORK_STATUS proposal leave_reason for OFF, or initial-profile employment.leave_reason_text for OFF. They remain nonblank, length-checked, and rejected on non-OFF where current contracts require.
4. Do not fabricate placeholder reason text or restricted-reason rows for empty input. Keep the audit/revision/event record, actor, action, timestamp, before/after and version when reason is NULL.
5. Normalize before idempotency hash calculation. Omitted/null/blank optional reason must replay consistently; a changed nonblank reason remains a changed request.
6. Keep reasonable per-operation length limits and backwards compatibility. Do not weaken any other validation, state transition, document/payment control, export scope/limit, or authorization.
7. Identify every NOT NULL reason_id and decision_reason_id constraint that prevents true absence. Give T1-A the minimal forward-only SQL delta; the migration remains exclusively owned by A. A NOT NULL database column is not, by itself, a business requirement.
8. Do not delete reason/audit history or edit any historical migration/checksum.

## Mandatory regressions

- For each covered operation, test omitted, null, blank, whitespace, valid nonblank, wrong type, and overlong values at the appropriate boundary.
- Verify omitted/null/blank persist no restricted-reason placeholder but still create the expected audit/history row.
- Verify equivalent normalized inputs use consistent idempotency/hash behavior; different valid text remains distinguishable where currently part of the hash.
- Verify all OFF transition/create paths reject missing/blank/overlong leave reason, and non-OFF paths retain their current leave-field prohibition.
- Run API/contract/UI tests for exports, documents, payment, change-request create/decision, status, account access and catalogs.
