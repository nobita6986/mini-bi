Extend the existing privileged-edit, worker-directory, and change-request SQL path so a currently assigned Team Leader can directly edit workers in the one current team they manage and review in-scope team requests. Support genuinely absent optional action reasons with the smallest forward-only migration set. Do not add roles, capabilities, policy tables, or another workflow.

## Required changes

1. Reuse the current Team Leader authority and request helpers where they provide the needed strict checks. Bind actor identity to the server-authenticated subject and app user. Keep one canonical strict current-team predicate shared by directory projection, row/request reads and decisions, and direct edit; do not copy a parallel policy. If the general read helper has a catalog-operator bypass, that branch must not establish Team Leader authority or project direct_edit.
2. Extend the existing worker-directory audience with the `team` resource scope and emit `allowed_actions.direct_edit` from the server. Set it only for a currently editable row in the Team Leader's one current managed team, or for the existing Admin/BoD path. Keep this a UI hint; `direct_entry_privileged_edit` remains the final check on every write. T1-B owns all TypeScript/API/UI consumers.
3. Restrict a Team Leader to that current team. Independently check the original row and proposed row. Ownership-affecting changes to recruiter_id, project_id, provider/team, or work date must remain in the same team and satisfy existing current project-team mapping. Reject missing, ambiguous, inactive, revoked, or out-of-scope rows.
4. Do not grant all scope. Do not trust client role/title/team. Preserve the current Admin/BoD authorization branch.
5. Preserve allowlists, type/domain validation, row locks, DRAFT/SUBMITTED state restriction, REVIEW lock, expected_version OCC, idempotency replay, snapshots, revisions, audit, and error behavior. Preserve OFF leave_reason validation in every status-writing path.
6. Ensure pending change requests remain pending and are not deleted or approved by a direct edit. A later decision with stale expected_version must fail atomically and preserve the direct edit.
7. Use the shared strict Team Leader predicate plus existing request-team/audience helpers for list/read/decision parity. Every item must belong to the same currently authorized team. Revoked/disabled/ambiguous Team Leaders must fail on their next RPC. Team Leaders may not self-approve. Keep the catalog-operator bypass out of Team Leader decision and mutation paths.
8. Do not widen RLS, grants, function owners, SECURITY DEFINER exposure, service-role access, or S0 ACL allowlist. Any new shared predicate must remain an internal non-PostgREST-executable helper with verified owner, fixed search_path, and explicit ACL; do not leave default PUBLIC EXECUTE. No changes to unrelated RPC ACLs.
9. Support optional action reasons only from the approved T1-C inventory. Omitted/null/blank optional reasons must persist as real NULL, not as synthetic restricted_reasons rows. Make only the required reason columns/checks nullable. Preserve leave_reason and leave_reason_text invariants. Keep audit rows and actor, action, time, before/after, and version even when the reason is NULL.
10. Normalize the reason before hashing so omitted, null, and blank have the same canonical hash. Preserve nonblank length/type checks and existing idempotency behavior. Do not change historical checksum history.

## Mandatory regressions

- Leader A can edit team A; Leader A and Leader B cannot edit each other's team or an out-of-scope target.
- Directory team scope returns only the Team Leader's current team; direct_edit is true only for authorized editable rows and the existing Admin/BoD path. A catalog-operator bypass alone never grants it.
- New/internal SQL helpers are absent from the PostgREST executable allowlist and cannot be called by anon/authenticated/service_role unless specifically required and approved; existing S0 ACL invariants remain unchanged.
- Reject revoked, disabled, inactive, duplicate/ambiguous assignment or scope; recheck on every RPC.
- Changes to recruiter/project/team are checked before and after; no transfer escape.
- Allowed status values still work; OFF without a nonblank leave reason fails for privileged edit and WORK_STATUS.
- DRAFT/SUBMITTED allowed; REVIEW/locked states denied.
- Direct edit does not change pending request state; stale request decision cannot overwrite newer version.
- Team A reviewer can read/decide team A request; Team B cannot. Multi-entry request crossing scope is denied as a whole. Staff cannot self-review. WORK_STATUS detail shows current and proposed status and the existing decision path works; do not broaden DOCUMENT or ENTRY_VOID policy.
- Optional reason absent/null/blank persists no reason row but keeps audit/revision; nonblank reason is recorded; OFF leave reason remains required.
- Run existing S0 ACL, R1 current-state, idempotency, document guard, Admin/BoD, status, and payment safety DB regressions unchanged.
