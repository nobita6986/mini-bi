## 3. Key Architectural & UI/UX Changes

### 3.1. Independent Change Request Module (`/direct-entry/change-requests`)
- Registered `id: "change-requests"` (`label: "Yêu cầu thay đổi"`, `path: "/direct-entry/change-requests"`, `capability: "change_requests"`) in `src/lib/navigation/registry.ts` with active prefix matching so `/direct-entry/change-requests` highlights **Yêu cầu thay đổi** rather than **Nhập liệu**.
- Server page `src/app/direct-entry/change-requests/page.tsx` enforces fail-closed access via `decideChangeRequestsPageAccess` and `probeHistoricalChangeRequestAccess` (`resolveChangeRequestHistoricalAccessForRequest`). Instead of probing `state: null` (which in Migration #129 requires `audience <> 'NONE'`), the server probes the 3 explicit R2.1 queues (`PROPOSER_PENDING`, `PROPOSER_RESOLVED`, `REVIEWER_RESOLVED` with `page_size: 1`) so active proposers and deciders who lost current scope/capability retain read-only access to their pending/resolved history, and `resolveNavActorForAppShell` keeps the **Yêu cầu thay đổi** menu visible via `hasHistoricalChangeRequests`.
- In `DirectEntryChangeRequestList` (`src/components/direct-entry/direct-entry-change-request-list.tsx`), every visible request renders either **Xem xét** (`state === "PENDING" && can_decide === true`) or **Xem chi tiết** (`!canReviewChangeRequest(request)`, including `PENDING` requests with `can_decide === false` and `can_withdraw === false`), while **Rút yêu cầu** is strictly gated by `canWithdrawChangeRequest(request)` (`state === "PENDING" && can_withdraw === true`).
- `ChangeRequestsWorkspace` (`src/components/direct-entry/change-requests-workspace.tsx`) binds directly to the R2.1 4-queue + `GLOBAL_AUDIT` contract:
  - **Proposer Mode:** `Tôi đã gửi` (`PROPOSER_PENDING`), `Lịch sử gửi` (`PROPOSER_RESOLVED`).
  - **Reviewer Mode:** `Chờ tôi duyệt` (`REVIEWER_PENDING`), `Lịch sử duyệt` (`REVIEWER_RESOLVED` — strictly `decided_by_user_id = actor`).
  - **Global Audit (Admin/BoD `@ all`):** `Lịch sử toàn hệ thống` (`GLOBAL_AUDIT` with `days=3|7|30|all` filter).
  - **Multi-Authority Mode Switch:** Reviewers who previously submitted requests can toggle `Lịch sử đề xuất của tôi` (`data-testid="toggle-proposer-history-mode"`) / `Quay lại hàng đợi duyệt` (`data-testid="toggle-reviewer-mode"`).

### 3.2. Read-Only Mode P0 in `DirectEntryChangeRequestReviewer`
- Updated `src/components/direct-entry/direct-entry-change-request-reviewer.tsx` with `const terminal = detail.state !== "PENDING"; const readOnlyView = terminal || !detail.can_decide;`.
- When `readOnlyView` is `true`, the dialog renders strictly from the immutable `detail.items[].proposal` snapshot (`historyRows`) and **skips fetching `/api/direct-entry/entries/[entryId]`**. This guarantees that a reassigned Staff or Leader viewing historical requests never hits a `403` from current worker entry scope checks, while current worker profile data and documents outside current scope remain protected.
- When `detail.state === "PENDING" && detail.can_decide === true`, the dialog continues to fetch `/api/direct-entry/entries/[entryId]` to display the full Before/After diff and Approve/Reject actions.

### 3.3. Cleanup of `/direct-entry` & Contextual Proposal Creation

- Replaced the native `window.confirm` in `onPersistedDelete` (`src/components/direct-entry/direct-entry-live.tsx`) with a Radix `AlertDialog` (`data-testid="confirm-delete-draft-row-dialog"`).
