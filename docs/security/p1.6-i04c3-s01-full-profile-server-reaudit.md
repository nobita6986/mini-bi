## 5. PII / projection matrix

### 5.1 In-transit PII handling

- **Request body**: validated, never logged. `readBoundedJson` (`full-profile-api.ts:39–74`) parses but does not log; the catch path returns `BODY_INVALID` without echoing the body.
- **Origin/CSRF guard**: `checkSameOriginRequest` rejects bad origins without leaking details; error code is `CSRF_REJECTED`.
- **Feature gate**: returns `NOT_FOUND` (404), not 403, to avoid fingerprinting.
- **Idempotency key**: validated as UUID v1–v8, but **not logged** anywhere. Idempotency records store only `app_user_id + action + key + request_hash + result` (`direct_entry_rpc_idempotency` schema unchanged from #1–#35).
- **Error responses**: only codes (`BATCH_INVALID`, `EMPLOYEE_CODE_DUPLICATE`, `BANK_NOT_ACTIVE`, etc.). The TS code sets `SAFE_CLIENT_CODES` (`full-profile-api.ts:11–22`) — **all** codes that can reach the client are non-PII; the repository's `SAFE_INVALID_CODES` (`full-profile-repository.ts:16–32`) is a strict subset of the API's allow-list, so any DB-thrown code path is filtered before reaching the client.
- **Audit log `changed_fields`**: only field-name strings (`'entry_created','worker_details','general_note'` + optional `'payment'` + `'employment_status'`). No values. (`…_foundation.sql:664–670`)
- **Audit log `resource_ref`**: only the new `entry_id::text` or `submission_id::text` (UUIDs). No name/code/PII. (`…_foundation.sql:665, 689`)
- **Revision snapshots**: `direct_entry_entry_snapshot` is replaced (`…_foundation.sql:118–178`) and now stores only `{ present: true/false }` markers for `worker_details` and `general_note`. Verified by the snapshot redaction test (`p1.6-i04c3-s01-db.test.mjs:303–316`) — none of `[001234567890, 09000000001, 000012345678, "Synthetic Account Holder", "Synthetic Address 1", "Synthetic private note", "Synthetic historical departure"]` appears in any `before_snapshot` or `after_snapshot`.

### 5.2 Read projection redaction

`direct_entry_read_projection` is replaced (`…_foundation.sql:180–283`) and now produces:

- `worker_details`: when `pii_view` is granted → full JSONB; otherwise → per-field `{state, present}` markers (no values).
- `general_note`: when `pii_view` is granted → text value; when null → `null`; otherwise → `{present:true}`.
- `payment.account_number`: when `payment_view` is granted → full value; otherwise → masked to last 4 digits via `repeat('•', greatest(length - 4, 0)) || right(value, 4)`. Verified by `p1.6-i04c3-s01-db.test.mjs:298–302` (`••••••••5678` for `000012345678`).
- `payment.bank_id, account_holder_name`: only exposed with `payment_view`.
- `documents`: when `document_view` is granted → array; otherwise → `[]`.

### 5.3 Anti-enumeration

The read projection raises `P0002 'entry not found'` when the entry doesn't exist (or is `deleted_at IS NOT NULL`) (`…_foundation.sql:198–201`). Out-of-scope reads propagate `42501 'resource scope denied'` (or `ACTOR_DENIED` from the API layer) which is **indistinguishable** from a `denied` no-match — verified by the integration test pattern at `p1.6-i04c3-s01-db.test.mjs:417–423` (a payment-view-denied user gets 42501 even when the row exists and they would otherwise be in scope).

**PASS — anti-enumeration preserved** (D22 invariant).
