# P1.6-T1B-S01 — react-data-grid direct-entry spike

## Recommendation

**GO-WITH-CONDITIONS** for a focused, spreadsheet-like entry form, not for full Google Sheets parity.

The exact package builds and server-prerenders on Next.js 16.3.8 with React 19.2.8. Its virtualized grid stayed responsive through 20,000 synthetic rows, but one custom 20,000-row size change measured 78.2 ms to the next paint. Multi-cell paste required custom code; copying a selected range is not provided by this prototype. Keep the beta dependency and range-copy gap as explicit decisions for P1.6-W04.

## 5. Synthetic benchmark

Production build, integrated Chromium, viewport 1366×768. Values are local observations, not a cross-device performance guarantee. “Size change” measures from choosing the row count through two animation frames, including synthetic row generation and validation. `performance.memory` is a Chromium heap estimate without forced GC and is indicative only.

| Rows | Size-change to next paint | Reported JS heap | Rendered grid rows (incl. header/overscan) | Freeze/scroll/edit |
|---:|---:|---:|---:|---|
| 500 | 5.8 ms | 9.1 MB | 22 | No visible freeze. |
| 5,000 | 19.8 ms | 9.0 MB | 22 | No visible freeze. |
| 20,000 | 78.2 ms | 10.7 MB | 22 | A single size-change update exceeded 50 ms; it completed without a sustained freeze. Editing the last virtualized row updated through the next frame in 41.1 ms. |

The constant rendered-row count and bounded heap growth support the library’s virtualization claim. The synthetic data-switch measurement includes this prototype’s row generation and whole-list validation, not just library render time.

## 6. Keyboard, clipboard, IME, and typeahead

- Arrow key moved the active cell; Tab moved it to the next column.
- Enter opened the relevant editor and committed select/date/text updates.
- An IME composition event prevented Enter from prematurely closing the text editor.
- `C` showed multiple recruiter suggestions; `Co` narrowed to 5 vendor results. ArrowDown + Enter chose an option and stored its stable ID.
- A synthetic clipboard event with a 2×4 TSV matrix populated project, date, employee code, and fake name for two rows. Single-cell copy was also exercised; range-copy is the remaining gap.
- The library does not supply application-specific typeahead, employee-code logic, duplicate validation, dirty state, or mobile list/drawer behavior; those are custom prototype code.

## 7. Responsive and accessibility smoke checks

- Desktop 1366×768: full grid; horizontal overflow is contained inside the intentional grid viewport. Body width remained 1366 px.
- Tablet 768×1024: grid remains visible and body width equals viewport width.
- Mobile 390×844: grid is hidden in favor of a row list and edit drawer; body had no horizontal overflow. The spike list intentionally caps its display at the first 100 rows.
- Grid has an accessible label and visible focus border. The drawer has a labelled dialog, labelled fields, initial focus, Escape close, and described employee-code errors. Dirty/error states include text/symbols, not color alone.
- Browser accessibility-tree smoke confirmed grid, dialog, field labels, and status text. This was not a NVDA/VoiceOver certification; focus trapping and native screen-reader behavior still need real-device validation.

## 9. Known limitations

- `7.0.0-beta.61` is prerelease software despite matching React 19.2 peers and passing the Next production build.
- Rectangular range selection/copy is not implemented; current-cell copy and custom matrix paste are available.
- Recruiter typeahead, multi-cell paste, data validation, and the mobile view need ownership and automated interaction tests if adopted.
- Benchmark measurements use synthetic rows on one integrated browser/machine. The 20,000-row size-change reached 78.2 ms; repeat on target hardware after the data contract and validation scope are known.
- Mobile list is limited to 100 rows; the drawer has no full keyboard focus trap.
- Save is deliberately a local visual-state control only. No API, persistence, or production data behavior is included.
